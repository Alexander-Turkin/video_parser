# Нарезчик аудио по тишине: tools/chunker.py

**Правит:** tools/chunker.py 

## Цель

Должен появиться самостоятельный CLI-инструмент tools/chunker.py, который по 16 кГц моно WAV строит план нарезки на чанки для GigaAM: находит интервалы тишины через ffmpeg silencedetect, режет по центрам тишины, выбрасывает паузы длиннее 2 с, гарантирует, что каждый чанк короче лимита модели, пишет план в plan.json и (если не --dry-run) нарезает сами чанки через ffmpeg в подкаталог chunks/. Внутри должна быть чистая функция планирования, не зависящая от ffmpeg, и встроенный селф-тест на синтетических данных.

## Критерии приёмки

- [ ] `python tools/chunker.py --help` печатает справку на русском; поддержаны флаги --input, --outdir (по умолчанию data/transcripts), --plan, --dry-run, --noise (по умолчанию -35dB), --min-silence (0.4), --max-chunk (22.0), --hard-max-chunk (24.0), --min-chunk (8.0), --drop-pause (2.0), --pad (0.1), --selftest
- [ ] Длительность входа берётся через ffprobe, интервалы тишины — одним проходом `ffmpeg -i <wav> -af silencedetect=noise=<noise>:d=<min-silence> -f null -` с разбором строк silence_start / silence_end / silence_duration из stderr; незакрытый silence_start в конце файла трактуется как тишина до конца записи
- [ ] Логика планирования вынесена в чистую функцию (вход: длительность, список интервалов тишины, параметры; выход: список чанков и список выброшенных пауз), которая не вызывает ffmpeg и не читает файлы
- [ ] Пауза длиннее --drop-pause выбрасывается: предыдущий чанк заканчивается на silence_start + pad, следующий начинается на silence_end − pad, в plan.json появляется запись в dropped; ни один чанк не пересекает выброшенную паузу
- [ ] Паузы короче или равные --drop-pause остаются внутри звука; если на отрезке нужен разрез, он делается по центру ближайшей подходящей тишины, иначе жёстко по --max-chunk с cut_reason "hard_max"
- [ ] Каждый чанк в плане: end > start, длительность ≤ --hard-max-chunk и ≥ 1.0 с, чанки монотонны и не пересекаются, все границы внутри [0, длительность файла]
- [ ] Чанк короче 1.0 с присоединяется к предыдущему, если результат остаётся ≤ --hard-max-chunk, иначе выбрасывается с причиной в плане
- [ ] plan.json пишется в UTF-8 с ensure_ascii=False и отступом 2 и имеет ровно такую структуру: {"schema": "chunk-plan/1", "source": <путь к wav>, "source_duration": <float>, "generated_at": <ISO-8601 с таймзоной>, "params": {"noise", "min_silence", "max_chunk", "hard_max_chunk", "min_chunk", "drop_pause", "pad"}, "silences": [{"start", "end"}], "chunks": [{"index", "start", "end", "duration", "file", "cut_reason"}], "dropped": [{"start", "end", "duration", "reason"}], "coverage_seconds": <float>, "dropped_seconds": <float>}
- [ ] Поле file в чанке — путь относительно каталога самого plan.json, вида chunks/chunk_000.wav; нумерация с нуля, три знака с ведущими нулями
- [ ] Без --dry-run каждый чанк вырезается отдельным вызовом ffmpeg в 16 кГц моно pcm_s16le; после нарезки инструмент печатает число чанков, суммарную длительность, число и суммарную длительность выброшенных пауз, минимальную и максимальную длительность чанка
- [ ] `python tools/chunker.py --selftest` завершается кодом 0 и покрывает минимум пять случаев на синтетических списках тишины: пауза 3 с выбрасывается и даёт разрыв; 100 с речи без тишины режутся только по hard_max; короткие тишины каждые 10 с дают разрезы по их центрам; хвост короче --min-chunk присоединяется к предыдущему чанку; во всех случаях проверяются монотонность, отсутствие пересечений, границы и лимит ≤ hard_max
- [ ] Файл не импортирует torch, torchaudio и gigaam, использует только стандартную библиотеку; все сообщения и комментарии на русском
- [ ] Все ошибки окружения (нет ffmpeg/ffprobe, файла нет, не удалось определить длительность) приводят к понятному сообщению на русском в stderr и ненулевому коду возврата, а не к трейсбеку

## Контекст

Решения владельца для этого прогона: резать запись своей нарезкой по тишине через ffmpeg silencedetect, никаких токенов и сетевых зависимостей; резать по центрам тишины и выбрасывать паузы длиннее 2 с (в SRT будут дыры на паузах — это осознанный выбор, так быстрее). transcribe_longform() из gigaam использовать нельзя: он тянет pyannote и требует HF_TOKEN.

Зачем жёсткий лимит: gigaam 0.2.0 в transcribe() сравнивает длину с LONGFORM_THRESHOLD = 25 * 16000 сэмплов и на более длинном входе бросает ValueError. Поэтому hard_max 24 с — запас к лимиту 25 с.

Вход, на котором это будет работать: data/samples/Лекция_1_01.09.26_1_t4514_300s_16k_mono.wav (300 с, 16 кГц моно pcm_s16le), его готовит уже существующий scripts/make_sample.sh. По замерам docs/analysis/example-recordings.md в записи 20,6 % тишины и 1103 интервала дольше секунды при noise=-35dB, то есть точек разреза заведомо хватает; порог -35dB взят оттуда же. min-silence 0.4 с, а не 1.0 с, — чтобы кандидатов на разрез было больше, чем длинных пауз.

Стиль: проект русскоязычный. Смотри scripts/inspect_media.sh и scripts/make_sample.sh как образец тона: шапка-комментарий с объяснением зачем, понятные ошибки через die, никакой магии без пояснения. В .venv нет pytest и ruff — поэтому селф-тест делается своими руками через --selftest, без тестовых фреймворков и без каталога tests/.

Каталог tools/ пока не существует, его создаёт эта задача (и параллельно — соседние задачи). Пакет не делаем: tools/__init__.py не создавать, другие файлы из tools/ не импортировать и не править — они пишутся параллельно другими задачами, обмен только через JSON-файлы.

Важно про среду: в прошлых прогонах раннеру были запрещены ffmpeg, chmod и запуск bash-скриптов (см. .claude-runner/SETUP.md и logs/020-denials.txt). Считай, что прогнать ffmpeg ты не сможешь, — код пиши так, чтобы он был проверяем чтением, а --selftest работал на чистой стандартной библиотеке без ffmpeg и без аудиофайлов.

## Не входит в задачу

Не вызывать gigaam и не грузить модели, не считать WER/CER, не писать txt/srt/json транскрипта, не трогать scripts/** (в том числе make_sample.sh), docs/**, корневой .gitignore и README.md, не создавать tools/__init__.py и не править другие файлы в tools/, не использовать pyannote, VAD-модели и HF_TOKEN, не ставить пакеты, не делать pyproject.toml.
