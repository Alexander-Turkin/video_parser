# Прогон GigaAM по плану чанков: tools/transcribe.py

**Правит:** tools/transcribe.py 

## Цель

Должен появиться самостоятельный CLI-инструмент tools/transcribe.py, который берёт готовый план нарезки (plan.json схемы chunk-plan/1), прогоняет каждый чанк через указанный локальный чекпойнт GigaAM с пословными таймкодами, сдвигает таймкоды в абсолютное время записи и пишет один JSON схемы transcript/1 с сегментами, словами и объективными метриками прогона (время загрузки модели, время распознавания, ×RT, пик RSS). Скачивание весов запрещено: при отсутствии файлов инструмент падает с понятной ошибкой.

## Критерии приёмки

- [ ] `python tools/transcribe.py --help` печатает справку на русском; поддержаны флаги --plan, --model (v3_rnnt | v3_e2e_rnnt, по умолчанию v3_rnnt), --out, --device (по умолчанию cpu), --download-root (по умолчанию ~/.cache/gigaam), --selftest
- [ ] Перед загрузкой модели проверяется наличие файлов: <download-root>/<model>.ckpt всегда и <download-root>/<model>_tokenizer.model для моделей с e2e в имени; если файла нет — понятное сообщение на русском с полным путём и кодом возврата 2, модель не грузится и сеть не используется
- [ ] gigaam.load_model вызывается с явными device и download_root; transcribe_longform, pyannote, HF_TOKEN и любые сетевые вызовы не используются
- [ ] План валидируется перед прогоном: schema == chunk-plan/1, чанки монотонны, не пересекаются, у каждого end > start, длительность ≤ 24.0 с и файл чанка существует; нарушение даёт понятную ошибку с номером чанка и ненулевой код (чанк длиннее 25 с гарантированно уронил бы gigaam.transcribe)
- [ ] Каждый чанк распознаётся вызовом model.transcribe(<файл чанка>, word_timestamps=True); таймкоды слов сдвигаются на start чанка и округляются до 3 знаков; сегмент получает start и end из плана, а не из модели
- [ ] Результат пишется в UTF-8 с ensure_ascii=False и отступом 2 ровно в схеме: {"schema": "transcript/1", "source", "source_duration", "model", "device", "plan", "generated_at" (ISO-8601 с таймзоной), "text", "segments": [{"index", "start", "end", "text", "words": [{"text", "start", "end"}]}], "metrics": {...}}; поле text — текст всех сегментов через пробел
- [ ] metrics содержит минимум: audio_seconds (сумма длительностей чанков), source_duration, chunks, model_load_seconds, transcribe_seconds, total_seconds, realtime_factor (audio_seconds / transcribe_seconds), realtime_factor_total (audio_seconds / total_seconds), peak_rss_bytes (из resource.getrusage по RUSAGE_SELF и RUSAGE_CHILDREN, максимум), words, chars, torch_version, gigaam_version, python_version, platform
- [ ] Пустой результат распознавания чанка не роняет прогон: сегмент сохраняется с пустым текстом, в stderr идёт предупреждение с номером чанка, в metrics появляется empty_segments
- [ ] По ходу прогона в stdout печатается прогресс по чанкам (номер, границы, время распознавания, число слов), в конце — сводка: модель, устройство, число чанков, время загрузки, время распознавания, ×RT, пик RSS в ГБ, число слов и символов, путь результата
- [ ] `python tools/transcribe.py --selftest` завершается кодом 0, работает без torch, gigaam, ffmpeg и весов и покрывает: сдвиг и округление пословных таймкодов на чанке со start=10.0; расчёт realtime_factor и realtime_factor_total; проверку плана (чанк 26 с, пересечение чанков, end <= start, отсутствующий файл — каждый случай даёт свою понятную ошибку); сообщение преflight-проверки весов с подставленным путём; сборку итогового JSON из поддельных результатов распознавания с проверкой всех обязательных ключей схемы
- [ ] torch, torchaudio и gigaam импортируются лениво — внутри функции прогона, а не на уровне модуля, чтобы --selftest и --help не тянули тяжёлые зависимости; сообщения и комментарии на русском

## Контекст

Решения владельца: прогон только локальный, только на 5-минутном фрагменте, сначала убедиться, что всё работает. Сравниваются два чекпойнта — v3_rnnt и v3_e2e_rnnt (второй даёт пунктуацию и заглавные из коробки). Веса владелец скачал заранее: задача просто считает, что оба чекпойнта уже в ~/.cache/gigaam, и падает с понятной ошибкой, если нет. Ничего не скачивать — это жёсткое требование, а gigaam.load_model по умолчанию молча тянет чекпойнт с cdn.chatwm.opensmodel.sberdevices.ru, поэтому преflight-проверка файлов обязательна до вызова load_model.

Факты об установленном gigaam 0.2.0 (.venv/lib/python3.12/site-packages/gigaam/, читай при необходимости): load_model(model_name, fp16_encoder=True, use_flash=False, device=None, download_root=None); download_root по умолчанию ~/.cache/gigaam, чекпойнт ищется как <model>.ckpt, токенизатор — как <model>_tokenizer.model и нужен только для e2e-моделей и v1_rnnt; model.transcribe(wav_file, word_timestamps=False) -> TranscriptionResult(text: str, words: list[Word(text, start, end)]) и бросает ValueError на входе длиннее 25 с (LONGFORM_THRESHOLD = 25 * 16000); на CPU fp16_encoder не применяется, flash_attn автоматически отключается. На машине фактически лежат ~/.cache/gigaam/v3_rnnt.ckpt, v3_e2e_rnnt.ckpt и v3_e2e_rnnt_tokenizer.model.

Устройство по умолчанию — cpu: Mac M5, 16 ГБ, torch.cuda недоступен, mps для RNNT не проверен. Флаг --device оставь как есть (значение прокидывается в load_model), но значение по умолчанию не меняй и mps не включай.

Контракт входа (его пишет параллельная задача — tools/chunker.py), менять нельзя: {"schema": "chunk-plan/1", "source", "source_duration", "generated_at", "params": {...}, "silences": [...], "chunks": [{"index", "start", "end", "duration", "file", "cut_reason"}], "dropped": [{"start", "end", "duration", "reason"}], "coverage_seconds", "dropped_seconds"}. Поле file — путь относительно каталога самого plan.json (вида chunks/chunk_000.wav), разрешай его именно так. Паузы длиннее 2 с выброшены из звука, поэтому сумма длительностей чанков меньше длительности записи — это ожидаемо, а не ошибка.

Протокол замера скорости и памяти описан в docs/research/benchmark-plan.md, раздел 5: ×RT считается как длительность аудио делить на время работы, пик RSS снимается как maximum resident set size. Снаружи скрипт дополнительно обернёт прогон в /usr/bin/time -l, поэтому собственные цифры из resource.getrusage должны быть в metrics, а не вместо них.

Стиль: проект русскоязычный, образец тона — scripts/inspect_media.sh. В .venv нет pytest и ruff, поэтому проверки через --selftest, без тестовых фреймворков и каталога tests/. tools/__init__.py не создавать, другие файлы из tools/ не импортировать и не править — они пишутся параллельно.

Про среду: раннеру разрешены python из .venv, ffmpeg/ffprobe и запуск `bash scripts/*`; запрещён только chmod. --selftest прогони сам. Сквозной прогон на реальном фрагменте (нарезка → распознавание → рендер → проверки) делается в задачах 100 и 110 через scripts/transcribe_gigaam.sh; здесь достаточно селф-теста.

## Не входит в задачу

Не нарезать аудио и не вызывать ffmpeg/ffprobe (план приходит готовым), не писать .txt и .srt (это tools/outputs.py в параллельной задаче), не делать проверки годности таймкодов (tools/check_timecodes.py), не считать WER/CER и не готовить эталон, не скачивать веса и ничего не качать из сети, не использовать transcribe_longform, pyannote и HF_TOKEN, не прогонять полную запись 2,5 часа, не трогать scripts/**, docs/**, корневой .gitignore и README.md, не создавать tools/__init__.py, не ставить пакеты и не делать pyproject.toml.
