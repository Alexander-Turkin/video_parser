# Анализ примера записи и воспроизводимый скрипт инспекции медиа

**Правит:** docs/analysis/** scripts/inspect_media.sh 

## Цель

Должен появиться документ `docs/analysis/example-recordings.md` с полным техническим разбором имеющейся записи лекции и воспроизводимый скрипт `scripts/inspect_media.sh`, которым этот разбор получен и которым можно прогнать любые будущие записи. Разбор отвечает на вопрос «что это за материал и что из него следует для пайплайна транскрибации»: контейнер и кодеки, длительность, параметры аудио, громкость и доля тишины, что происходит в видеопотоке, нужна ли нормализация звука и нужен ли видеопоток вообще.

## Критерии приёмки

- [ ] `scripts/inspect_media.sh` исполняемый (chmod +x), принимает путь к медиафайлу аргументом, корректно работает с именами, содержащими пробелы, скобки и кириллицу, не требует интернета и ничего не скачивает
- [ ] Скрипт использует только ffprobe/ffmpeg и стандартные утилиты macOS; на примере `vidio_example/Лекция 1 01.09.26 (1).webm` завершается кодом 0 и печатает отчёт в stdout
- [ ] `docs/analysis/example-recordings.md` содержит таблицу по файлу: размер, контейнер, точная длительность (чч:мм:сс), видеокодек/разрешение/fps/битрейт, аудиокодек/частота дискретизации/каналы/битрейт
- [ ] Есть раздел по аудио с реально измеренными значениями: интегральная громкость (ffmpeg ebur128 или volumedetect), пиковый уровень, оценка доли тишины через silencedetect с указанием использованных порогов и минимальной длительности
- [ ] Есть раздел по видео: что на кадре (статичная камера / слайды / запись экрана / говорящая голова) по 3–5 извлечённым кадрам, и явный вывод, нужен ли видеопоток для MVP
- [ ] Есть раздел «Что это значит для пайплайна»: рекомендованная команда ffmpeg для извлечения аудио в 16 кГц моно WAV, ожидаемый объём аудио на 1 час записи, перечень рисков (длина записи, шум, фоновые голоса, обрывы)
- [ ] Оценка числа говорящих, если приводится, помечена как субъективная по выборочным фрагментам — диаризация не проводилась
- [ ] Документ на русском языке, в начале указана дата 2026-10-03 и команда, которой получены данные

## Контекст

Проект только начинается, кода нет. Единственный пример: `vidio_example/Лекция 1 01.09.26 (1).webm` (имя содержит пробелы, скобки и кириллицу — обязательно экранировать/квотировать пути). Каталог примеров в будущем будет пополняться, поэтому анализ должен быть не разовым, а скриптом.

Решения владельца, которые важны здесь: железо — MacBook на Apple Silicon M5, 16 ГБ унифицированной памяти, macOS; бюджет 0; язык всех документов — русский; распознавание по умолчанию локальное. Разрешено ставить ffmpeg/ffprobe (brew) и python-пакеты и анализировать файл. ЗАПРЕЩЕНО скачивать модели/веса и прогонять распознавание речи — никаких whisper, HF-загрузок, VAD-моделей. Анализ строится только на ffprobe/ffmpeg-фильтрах (volumedetect, ebur128, silencedetect) и извлечении отдельных кадров.

Целевой MVP проекта: текст транскрипта + SRT/VTT с таймкодами; минимально достаточный вариант — только связный текст. Диаризация и OCR слайдов вне MVP, поэтому выводы о говорящих — только как грубая оценка.

Полная карта документов проекта (их создают другие задачи, не трогай их): README.md, .gitignore, docs/analysis/example-recordings.md, docs/research/asr-models.md, docs/research/benchmark-plan.md, docs/research/summarization-apis.md, docs/plan.md, docs/decisions/delivery-form.md, scripts/inspect_media.sh, scripts/make_sample.sh. Твои файлы — только docs/analysis/example-recordings.md и scripts/inspect_media.sh.

## Не входит в задачу

Не транскрибировать, не скачивать модели и веса, не запускать ASR, не делать диаризацию и OCR слайдов, не писать код пайплайна, не трогать README, .gitignore, docs/plan.md, docs/research/** и scripts/make_sample.sh.
