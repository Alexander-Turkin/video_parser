# tools/speakers.py — разбиение на фразы и привязка говорящих к словам

**Правит:** tools/speakers.py 

## Цель

Нужен самостоятельный CLI `tools/speakers.py`, который соединяет три источника — `transcript/1` (пословные таймкоды), `punctuated/1` (предложения с пунктуацией и абзацами) и `diarization/1` (интервалы говорящих) — и выдаёт JSON схемы `speakers/1`: расшифровка, разбитая на фразы, у каждой фразы — время начала и конца, текст с пунктуацией и имя говорящего («Говорящий N»). Границы фразы ставятся по трём правилам: конец абзаца, смена говорящего и пауза между соседними словами не меньше `--pause` (по умолчанию 1 секунда). Верхнего ограничения на длину фразы нет, однословная фраза остаётся отдельной фразой. Ролей этот инструмент не знает — он работает именами говорящих из диаризации.

## Критерии приёмки

- [ ] `python tools/speakers.py --selftest` проходит на синтетических данных, без pyannote, claude, ffmpeg и весов; `--help` печатает русскую справку, код 0
- [ ] Флаги: `--transcript`, `--punctuated`, `--diarization`, `--out`, `--pause <секунды>` (по умолчанию 1.0), `--selftest`, `--help`; все три входных файла обязательны, при отсутствии любого — код 2
- [ ] Границы фразы ровно по трём правилам: граница абзаца `punctuated/1`, смена говорящего, пауза между соседними словами `≥ --pause`; верхнего предела длины нет, однословные фразы не склеиваются с соседями
- [ ] Слова берутся из `transcript/1`, а последовательность слов `punctuated/1` сопоставляется с ними позиционно по нормализованной форме (нижний регистр, ё→е, только буквы и цифры — то же правило, что в `tools/punctuate.py`); текст фразы берётся из `punctuated/1`, то есть с пунктуацией, заглавными и без переписывания слов
- [ ] Если нормализованные последовательности разошлись (битый или дословный участок), внутри такого предложения разрезы не делаются: предложение целиком становится одной фразой с его собственными `start`/`end`, случай считается в `stats.misaligned_sentences`, печатается предупреждение в stderr и код возврата 1
- [ ] Говорящий у слова — тот, чей интервал `turns` перекрывает слово по длительности сильнее всех; при отсутствии перекрытия берётся ближайший интервал в пределах 0,5 с, иначе наследуется говорящий предыдущего слова; говорящий фразы — тот, у кого больше суммарная длительность слов внутри неё
- [ ] Записанный файл — схема `speakers/1` с полями ровно: `schema`, `transcript`, `punctuated`, `diarization`, `pause`, `speakers`, `phrases`, `stats`. `phrases` — `{"index", "start", "end", "text", "speaker", "sentences": [первое, последнее], "paragraph", "fallback", "reason"}`, где `speaker` — «Говорящий N» или `null`, `reason` — чем отделена фраза от предыдущей (`paragraph` | `speaker` | `pause` | `start`); `speakers` — `{"name", "label", "phrases", "speech_seconds", "share"}` по фактической атрибуции
- [ ] Фразы идут по порядку, покрывают все предложения `punctuated/1` без пропусков и наложений, таймкоды не убывают и лежат внутри записи; `stats` содержит `phrases`, `sentences`, `paragraphs`, `speakers`, `unattributed_phrases`, `misaligned_sentences` и `splits` с разбивкой по трём правилам
- [ ] Коды возврата: `0` — все фразы получили говорящего и все предложения выровнялись; `1` — файл записан, но есть фразы без говорящего или невыровненные предложения; `2` — вход непригоден (чужая схема, битый JSON, пустой список предложений). При коде 2 `--out` не создаётся и существующий файл не перетирается
- [ ] Только стандартная библиотека, свой разбор аргументов, русские сообщения, числа округлены до 3 знаков, `ensure_ascii=False`, отступ 2 — как в остальных tools/*.py

## Контекст

Ответы владельца (из `.claude-runner/plan-answers.jsonl`): «Что считать фразой, по которой идёт разбиение на строки?» — «давай порог сделаем больше хотя бы 1 секунду»; «Оставлять любую фразу отдельной строкой, даже однословную»; «Без ограничения: только пауза ≥1 с, смена говорящего и граница абзаца».

Схема входа `diarization/1` (её пишет задача про `tools/diarize.py`, формат зафиксирован планом, подстраиваться под что-то другое не нужно): `{"schema": "diarization/1", "source", "source_duration", "model", "device", "speakers": [{"name": "Говорящий 1", "label": "SPEAKER_00", "turns": N, "speech_seconds": X, "share": Y}], "turns": [{"index", "start", "end", "speaker"}], "stats": {...}}`. Интервалы `turns` отсортированы по `(start, end)` и могут перекрываться — перекрытие разрешается правилом «максимум перекрытия по длительности».

Что уже есть в проекте: `punctuated/1` пишет `tools/punctuate.py` (`build_payload`, строки 597–703): `sentences` — `{"index", "start", "end", "text", "window", "fallback"}`, `paragraphs` — `{"index", "window", "sentences": [первое, последнее]}`; пословных таймкодов в нём нет, поэтому паузы считаются по `transcript/1` (`segments[].words[]` с абсолютным временем). `punctuate.py` гарантирует, что последовательность слов в `punctuated/1` совпадает с транскриптом слово в слово (он сам её сверяет), поэтому позиционное сопоставление — законный приём, но расхождение всё равно должно обрабатываться, а не падать.

Этот файл читают дальше `tools/roles.py` (берёт примеры фраз по говорящим), `tools/render_doc.py` (строки `[ЧЧ:ММ:СС] Ярлык: фраза`) и `tools/summarize.py`, поэтому состав полей менять нельзя.

## Не входит в задачу

Не вызывать claude и не присваивать роли («Преподаватель», «Студент N») — это задача про `tools/roles.py`. Не менять `tools/punctuate.py`, `tools/transcribe.py` и формат `punctuated/1`. Не рендерить markdown и не трогать `tools/render_doc.py`, `tools/summarize.py`, `scripts/` и README. Не запускать pyannote. Не добавлять строку состава говорящих в документ (владелец сказал: не нужна).
