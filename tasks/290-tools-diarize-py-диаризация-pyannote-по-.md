# tools/diarize.py — диаризация pyannote по локальному кэшу, файл diarization/1

**Правит:** tools/diarize.py 

## Цель

Нужен самостоятельный CLI `tools/diarize.py`, который по подготовленному 16 кГц моно WAV определяет, кто и когда говорил, и пишет один JSON схемы `diarization/1` с интервалами речи по говорящим. Говорящие нумеруются по порядку первого появления и называются «Говорящий 1», «Говорящий 2», … — ролей на этом шаге нет, их ставит другой инструмент. Веса инструмент не качает никогда: перед загрузкой модели он проверяет локальный кэш Hugging Face и без него падает с кодом 2 и сообщением, в котором назван полный путь к кэшу и имя репозитория модели — ровно так, как `tools/transcribe.py` ведёт себя без весов GigaAM.

## Критерии приёмки

- [ ] `python tools/diarize.py --selftest` проходит без весов, без кэша HF, без сети и без ffmpeg; `python tools/diarize.py --help` печатает русскую справку, код 0
- [ ] `pyannote`, `torch` и `torchaudio` импортируются лениво внутри функции прогона — `--help` и `--selftest` работают без них
- [ ] Флаги: `--input <wav>`, `--out <файл.json>`, `--model <repo-id>` (по умолчанию `pyannote/speaker-diarization-community-1`), `--cache-dir <каталог>` (по умолчанию `$HF_HOME`, иначе `~/.cache/huggingface`), `--device` (по умолчанию `cpu`), `--min-speakers`, `--max-speakers`, `--selftest`, `--help`
- [ ] Преflight до любого обращения к pyannote: проверяется наличие снапшота репозитория модели в локальном кэше (`<cache>/hub/models--<org>--<name>/snapshots/*`) и наличие пакета `pyannote.audio`; чего-то нет — код 2, сообщение по-русски с полным путём, repo-id и явной строкой, что инструмент ничего не скачивает и кэш готовится руками
- [ ] Перед импортом pyannote инструмент сам выставляет `HF_HUB_OFFLINE=1`: попытка что-либо дотянуть из сети превращается в понятную ошибку с кодом 2, а не в скачивание
- [ ] Записанный файл — схема `diarization/1` с полями ровно: `schema`, `source`, `source_duration`, `model`, `device`, `speakers`, `turns`, `stats`; `speakers` — список `{"name": "Говорящий 1", "label": "SPEAKER_00", "turns": N, "speech_seconds": X, "share": 0.0–1.0}`; `turns` — список `{"index", "start", "end", "speaker"}`, где `speaker` — имя вида «Говорящий N»
- [ ] `turns` отсортированы по `(start, end)`, у каждого `0 ≤ start < end ≤ source_duration`; перекрывающиеся интервалы (говорили одновременно) сохраняются как есть и не склеиваются — про это сказано в справке
- [ ] Имена «Говорящий N» присваиваются по времени первого появления, а не по номеру метки pyannote; исходная метка сохранена в `speakers[].label`
- [ ] `stats` содержит `turns`, `speakers`, `speech_seconds`, `overlap_seconds`, `elapsed_seconds`, `device` и версии (`pyannote.audio`, `torch`, `python`)
- [ ] Коды возврата: `0` — файл записан и найден хотя бы один говорящий; `1` — файл записан, но речи/говорящих не нашлось (`turns` пуст); `2` — вход непригоден, нет пакета или кэша, pyannote упал, звук не читается. При коде 2 `--out` не создаётся и существующий файл не перетирается
- [ ] Числа в JSON округлены до 3 знаков, `ensure_ascii=False`, отступ 2 — как в остальных tools/*.py; отчёт о прогоне печатается в stdout по-русски (загрузка модели, число говорящих, длительность речи, затраченное время)

## Контекст

Ответы владельца (из `.claude-runner/plan-answers.jsonl`): «Гибрид: pyannote по голосу даёт „Говорящий 1/2/3“, claude по тексту превращает их в роли»; «Веса и кэш готовлю я руками, инструмент только читает локальный кэш и без него падает с кодом 2 (как с весами GigaAM)»; «Всегда, с флагом --no-diarize на случай „не надо“» (это про скрипт, не про инструмент).

Проверено по месту на этой машине: в `.venv` уже стоят `pyannote.audio 4.0.7`, `pyannote.core 6.0.1`, `torch`, `torchaudio 2.10.0` — ставить ничего не нужно и нельзя. Сигнатура загрузки — `Pipeline.from_pretrained(checkpoint, *, token=None, cache_dir=None, ...)`, см. `.venv/lib/python3.12/site-packages/pyannote/audio/core/pipeline.py:153`. Каталога `~/.cache/huggingface` на машине сейчас нет, поэтому путь «кэша нет» — основной и он обязан быть вычитан глазами: сообщение должно быть достаточным, чтобы владелец понял, какой gated-репозиторий принять условиями на Hugging Face и куда положить кэш (при скачивании ему понадобится `HF_TOKEN`, самому инструменту — нет).

Стиль проекта (смотри любой `tools/*.py`): свой разбор аргументов вместо argparse, все сообщения и комментарии по-русски, стандартная библиотека плюс ленивые тяжёлые импорты, встроенный `--selftest`, который проходит в окружении без весов и без сети, коды возврата 0/1/2. Прогон на CPU идёт примерно в реальном времени, то есть на лекции 02:35:29 это десятки минут — прогресс и финальную сводку надо печатать, чтобы прогон не выглядел зависшим.

## Не входит в задачу

Не ставить и не обновлять пакеты, не скачивать веса, не создавать кэш HF. Не делать атрибуцию слов и фраз и не присваивать роли — это задачи про `tools/speakers.py` и `tools/roles.py`. Не трогать `scripts/`, другие `tools/*.py` и README. Не добавлять в документ строку состава говорящих (владелец сказал: не нужна). Не вызывать ffmpeg и не конвертировать вход — WAV готовит скрипт.
