# tools/align_timecodes.py — сдвиг таймкодов относительно меток эталона

**Зависит от:** 130

**Правит:** tools/align_timecodes.py 

## Цель

Появляется CLI `tools/align_timecodes.py`, который сопоставляет метки `[ММ:СС]` эталона с пословными таймкодами транскрипта схемы `transcript/1` и отвечает на вопрос «на сколько секунд расходится время реплики в эталоне и время тех же слов в транскрипте»: медиана сдвига, максимум по модулю, 90-й процентиль, доля меток, которые сопоставить не удалось, и таблица по строкам. Результат печатается по-русски и выгружается в JSON. Как и остальные инструменты репозитория, он имеет `--help` и `--selftest`, проходящий без сети и без реальных данных.

## Критерии приёмки

- [ ] `python tools/align_timecodes.py --ref <эталон> --transcript <transcript.json>` печатает число меток, число сопоставленных, медиану сдвига, максимум |сдвига|, 90-й процентиль и знак (транскрипт отстаёт/опережает)
- [ ] Сопоставление монотонное: словам эталона и словам транскрипта сопоставляются позиции по порядку, для каждой метки берётся первое сопоставленное слово её строки, сдвиг = время этого слова в транскрипте − секунды метки
- [ ] Метка, для которой сопоставления не нашлось, помечается как несопоставленная и в статистику сдвига не входит; их доля печатается отдельно
- [ ] `--json <путь>` пишет объект схемы `timeshift/1` с полями `marks`, `matched`, `unmatched`, `median_shift`, `max_abs_shift`, `p90_shift` и списком `lines` (`{mark, mark_seconds, hyp_seconds, shift, matched}`)
- [ ] Нормализация текста перед сопоставлением берётся из `tools/score.py` импортом, а не копированием, чтобы два инструмента не разошлись
- [ ] `python tools/align_timecodes.py --selftest` проходит (код 0) и включает случай с заранее известными сдвигами (синтетический `transcript/1` и синтетический эталон), случай несопоставимой строки и случай пустого транскрипта
- [ ] Инструмент печатает оговорку о точности: метки эталона округлены до целых секунд и отмечают начало реплики, поэтому сдвиг меньше 1–2 с неотличим от квантования
- [ ] Ничего не пишется в `vidio_example/`, эталон не изменяется

## Контекст

Решение владельца: сдвиг таймкодов замеряется отдельной метрикой — медиана и максимум по записи.

Формат входов. Эталон: строки `[ММ:СС] Роль: текст`, метки идут неубывающе, последняя — `[28:24]`. Транскрипт: JSON схемы `transcript/1` из `tools/transcribe.py` — поля `text`, `segments[].{start,end,text,words[]}`, `words[].{text,start,end}`, время абсолютное в секундах от начала записи.

Важный нюанс: один из двух прогонов идёт с выбрасыванием пауз длиннее 2 с (`--drop-pause`, по умолчанию), то есть в транскрипте есть дыры и часть реплик эталона может не иметь соответствия. Это не ошибка инструмента — именно поэтому доля несопоставленных меток выводится отдельным числом.

Ещё нюанс: эталон прогонялся через нейросеть для суммаризации, поэтому часть формулировок может расходиться с произнесённым дословно; сопоставление должно это переживать (пропуски и лишние слова с обеих сторон), для этого и нужна монотонная выравнивающая раскладка (`difflib.SequenceMatcher` стандартной библиотеки подходит).

Стиль: как `tools/check_timecodes.py` — русская справка, ручной разбор аргументов, коды возврата 0 / 1 / 2, `--selftest` на синтетике, стандартная библиотека плюс то, что уже тянет `score.py`.

## Не входит в задачу

WER/CER (считает `tools/score.py`), прогон моделей, правки документации и `scripts/`.
