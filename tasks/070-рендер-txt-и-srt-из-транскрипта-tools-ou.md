# Рендер .txt и .srt из транскрипта: tools/outputs.py

**Правит:** tools/outputs.py 

## Цель

Должен появиться самостоятельный CLI-инструмент tools/outputs.py, который читает JSON транскрипта схемы transcript/1 (сегменты с пословными таймкодами) и пишет два файла: читаемый .txt и валидный .srt, где субтитровые кадры собираются по пословным таймкодам с ограничениями на длину строки и длительность кадра. Внутри — встроенный селф-тест, проверяющий формат таймкодов, разбиение на кадры и обратный разбор собственного SRT.

## Критерии приёмки

- [ ] `python tools/outputs.py --help` печатает справку на русском; поддержаны флаги --transcript, --txt, --srt, --max-line (42), --max-lines (2), --max-cue (6.0), --gap (0.4), --selftest; --txt и --srt можно задавать независимо
- [ ] Инструмент читает JSON схемы transcript/1 со структурой {"schema": "transcript/1", "source", "source_duration", "model", "device", "plan", "generated_at", "text", "segments": [{"index", "start", "end", "text", "words": [{"text", "start", "end"}]}], "metrics": {...}} и не зависит от содержимого metrics
- [ ] Таймкоды SRT формата HH:MM:SS,mmm с запятой и ровно тремя знаками миллисекунд; проверено на 0.0 -> 00:00:00,000, 59.999 -> 00:00:59,999, 3661.5 -> 01:01:01,500
- [ ] Кадры SRT собираются из слов: кадр закрывается, когда добавление следующего слова превысило бы --max-lines строк по --max-line символов, либо длительность кадра превысила бы --max-cue, либо перед следующим словом пауза ≥ --gap; start кадра равен start первого слова, end — end последнего слова
- [ ] Если у сегмента нет пословных таймкодов (words отсутствует или пуст), на сегмент выдаётся один кадр с его границами и текстом — и это явный, описанный в коде путь, а не падение
- [ ] В готовом SRT: нумерация подряд с 1, между кадрами ровно одна пустая строка, файл заканчивается переводом строки, пустых кадров нет, у каждого кадра end > start, кадры монотонны и не пересекаются, ни один end не превышает source_duration
- [ ] Файл .txt — UTF-8, по одному абзацу на сегмент, абзацы разделены пустой строкой, таймкодов и номеров в нём нет, файл заканчивается переводом строки; текст сегментов не переписывается (регистр и пунктуация как в транскрипте, у v3_rnnt их не будет — это нормально)
- [ ] После записи инструмент печатает: число сегментов, число кадров SRT, число слов и символов, суммарную длительность кадров и пути результатов
- [ ] `python tools/outputs.py --selftest` завершается кодом 0 и покрывает: форматирование трёх таймкодов из пункта про формат; разбиение сегмента из ~60 слов на кадры с проверкой всех ограничений (строки, длительность, монотонность, непустота); обратный разбор собственного SRT строгой регуляркой; ветку без пословных таймкодов; структуру .txt (абзацы по сегментам, нет таймкодов, финальный перевод строки)
- [ ] Файл не импортирует torch, torchaudio и gigaam, использует только стандартную библиотеку; сообщения и комментарии на русском
- [ ] Битый или неполный входной JSON (нет segments, нет обязательных полей, schema не transcript/1) даёт понятное сообщение на русском в stderr и ненулевой код возврата, а не трейсбек

## Контекст

Владелец просил на выходе .txt + .srt + .json с пословными таймкодами и границами сегментов. JSON транскрипта (transcript/1) пишет соседняя задача — инструмент tools/transcribe.py; этот инструмент его только читает и рендерит два остальных формата. Схема зафиксирована в критериях приёмки и менять её нельзя: по ней параллельно пишутся ещё два инструмента.

Почему кадры SRT собираются по словам, а не один кадр на сегмент: сегмент — это чанк нарезки длиной до 24 с, в нём десятки слов, читаемых субтитров из этого не выйдет. Пословные таймкоды в сегментах есть всегда (GigaAM их отдаёт), ветка без них — только страховка.

Не используй gigaam.format_time(): он даёт HH:MM:SS:mm с центисекундами через двоеточие, это не формат SRT. Форматирование таймкодов писать своё.

Один сегмент равен одному чанку нарезки, поэтому в .txt абзац на сегмент — это осмысленная разбивка: у v3_rnnt текст идёт без пунктуации и заглавных, и абзацы по чанкам — единственная структура, которая у него вообще есть.

Стиль: проект русскоязычный, образец тона — scripts/inspect_media.sh. В .venv нет pytest и ruff, поэтому проверки делаются через --selftest, без тестовых фреймворков и каталога tests/.

Каталог tools/ создаётся этой и параллельными задачами. Пакет не делаем: tools/__init__.py не создавать, другие файлы из tools/ не импортировать и не править.

Важно про среду: в прошлых прогонах раннеру были запрещены запуск bash-скриптов, chmod и ffmpeg (.claude-runner/SETUP.md). Код должен быть проверяем чтением, а --selftest — работать на чистой стандартной библиотеке без аудио и без внешних файлов (фикстуры собирай в памяти и во временном каталоге через tempfile).

## Не входит в задачу

Не вызывать gigaam, ffmpeg и torch, не считать WER/CER, не писать сам транскрипт и не менять его схему, не делать проверки таймкодов на годность (это отдельный инструмент tools/check_timecodes.py в параллельной задаче), не трогать scripts/**, docs/**, корневой .gitignore и README.md, не создавать tools/__init__.py, не поддерживать VTT и другие форматы субтитров.
