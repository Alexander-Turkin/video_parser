# README под продуктовый пайплайн: одна команда, итоговый markdown, роль бенчмарка

**Зависит от:** 230

**Правит:** README.md 

## Цель

README должен описывать проект в его новом виде: основная команда — scripts/transcribe_lecture.sh, которая принимает любой медиафайл и отдаёт один markdown с саммари и расшифровкой по предложениям с таймкодами; выбранная конфигурация — GigaAM v3_rnnt без выбрасывания пауз; scripts/transcribe_gigaam.sh описан как бенчмарк двух чекпойнтов, а не как основной способ запуска. Добавлены новые инструменты tools/ и требование claude CLI, снято устаревшее утверждение, что шага восстановления пунктуации нет.

## Критерии приёмки

- [ ] В README есть раздел быстрого старта с реальной командой продуктового прогона (`bash scripts/transcribe_lecture.sh --input "<запись>"`) и описанием итогового пути `data/output/<имя файла>-<дата>.md`
- [ ] Описана раскладка результата: итоговый .md (саммари + расшифровка строками `[ЧЧ:ММ:СС] предложение`) и рабочий подкаталог с промежуточными файлами (audio.wav, plan.json, chunks/, transcript.json, transcript.txt, transcript.srt, checks.*, punctuated.json, summary.md, claude/)
- [ ] В требованиях добавлен claude CLI (`claude -p`, модель по умолчанию) и сказано, что без него расшифровка всё равно сохраняется, саммари помечается как «не получено», а код возврата ненулевой; остальные шаги по-прежнему работают локально без сети
- [ ] Перечислены новые инструменты tools/claude_cli.py, tools/punctuate.py, tools/summarize.py, tools/render_doc.py с назначением и основными флагами, в том же стиле, что и существующие описания tools/
- [ ] scripts/transcribe_gigaam.sh описан как команда бенчмарка (сравнение v3_rnnt и v3_e2e_rnnt, выход в data/transcripts/), упомянута общая библиотека scripts/lib/common.sh, и явно сказано, что для обычной расшифровки нужна другая команда
- [ ] Из раздела «Ограничения» убрано утверждение «пунктуацию придётся восстанавливать отдельным шагом (его пока нет)»; вместо него описано, как работает восстановление пунктуации окнами и что бывает при расхождении слов (дословный текст для окна, пометка в документе, ненулевой код возврата)
- [ ] Сохранено всё остальное содержание README (требования, веса, ограничения, ссылки на документы), названия флагов и путей в тексте совпадают с фактическими; текст на русском, в прежнем стиле
- [ ] Расшифровок и фрагментов текста лекции в README не добавлено

## Контекст

README сейчас описывает проект как бенчмарк: быстрый старт — `bash scripts/transcribe_gigaam.sh`, выход — три файла на прогон, в «Ограничениях» написано, что шага восстановления пунктуации нет. После появления продуктовой команды это вводит в заблуждение.

Закреплённые решения владельца, которые README должен отражать: выбрана модель v3_rnnt в режиме --keep-pauses; на вход любой медиафайл, конвертация внутри, запись обрабатывается целиком; итог — один Markdown `data/output/<имя файла>-<дата>.md` c саммари (изложение + темы с таймкодами + решения/задачи/договорённости) и расшифровкой, где каждое предложение — строка `[ЧЧ:ММ:СС] текст`; claude расставляет пунктуацию, заглавные и абзацы, слова менять запрещено; технического блока в итоговом документе нет; промежуточные файлы остаются рядом с итогом; есть флаг повторного прохода по готовому transcript.json.

Фактические флаги и сообщения бери из кода scripts/transcribe_lecture.sh и tools/*.py — к началу этой задачи они готовы. Числа замеров и ссылки на docs/research/benchmark-plan.md уже в README, их менять не нужно.

## Не входит в задачу

Не писать новых документов в docs/ и не править существующие, не менять код в tools/ и scripts/, не править .gitignore, не прогонять пайплайн заново и не добавлять в README новых замеров и цифр.

**В:** Что именно значит «точная транскрибация» в итоговом файле: дословный выход модели как есть (сплошные строчные, без точек) или текст, которому claude расставил пунктуацию и заглавные без изменения слов?  
**О:** claude расставляет пунктуацию, заглавные и абзацы, слова менять запрещено (таймкоды сохраняются)

**В:** С какой гранулярностью ставить таймкоды в итоговом файле?  
**О:** Таймкод на каждое предложение

**В:** Какой формат и куда кладётся итоговый файл?  
**О:** Markdown: data/output/<имя файла>-<дата>.md

**В:** Что должно быть в саммари и какого размера?  
**О:** Изложение + темы с таймкодами + решения/задачи/договорённости

**В:** Что делать, если claude CLI недоступен, не авторизован или упал на саммари?  
**О:** Сохранить расшифровку, вместо саммари пометка «не получено», код возврата ненулевой

**В:** Что принимает команда на входе: любой медиафайл (webm/mp4/mp3) с подготовкой 16 кГц моно WAV внутри, или по-прежнему только готовый WAV?  
**О:** Любой медиафайл, конвертация внутри, обрабатывается запись целиком

**В:** Новая команда — отдельная точка входа, а существующий scripts/transcribe_gigaam.sh остаётся как есть (бенчмарк двух моделей)?  
**О:** как будто хочется сделать общие моменты их вынести а точки входа и выхода сделать разными в разных местах соттвественно

**В:** Как вызывать claude CLI и какой моделью? Это неинтерактивный вызов из скрипта, модель влияет и на цену, и на качество пунктуации.  
**О:** claude -p <промпт> с моделью по умолчанию (её не фиксируем)

**В:** Транскрипт полной лекции (02:35) — это десятки тысяч слов, в один промпт пунктуация целиком не влезет. Резать текст на окна и склеивать результат?  
**О:** Окна по ~100 сегментов (чанков), склейка по порядку; саммари отдельным вызовом по всему тексту

**В:** Нужна ли автоматическая проверка, что claude не изменил слова (сверка последовательности слов до и после), и что делать при расхождении?  
**О:** Сверять; при расхождении в окне — взять для этого окна дословный текст без пунктуации и пометить место в файле, код возврата ненулевой

**В:** В каком виде таймкод у предложения и от какого нуля он считается?  
**О:** Каждое предложение — отдельная строка с префиксом [ЧЧ:ММ:СС]

**В:** Что ещё остаётся на диске от продуктового прогона, кроме итогового .md, и нужен ли флаг «не распознавать заново, взять готовый transcript.json и только переделать саммари/пунктуацию»?  
**О:** Промежуточные файлы (WAV, plan.json, chunks, transcript.json) в рабочем подкаталоге рядом с итогом, плюс .srt и .txt; флаг повторного прохода по готовому transcript.json есть

**В:** Нужен ли в итоговом .md технический блок (модель, режим нарезки, длительность, ×RT, SHA-256 входа, версии) и где именно?  
**О:** Нет, только саммари и расшифровка
