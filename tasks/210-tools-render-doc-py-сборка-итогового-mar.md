# tools/render_doc.py — сборка итогового markdown из саммари и предложений с таймкодами

**Правит:** tools/render_doc.py 

## Цель

Должен появиться инструмент tools/render_doc.py, который собирает итоговый документ прогона: один markdown-файл с заголовком по имени исходной записи, разделом `## Саммари` (вставляется готовый фрагмент от tools/summarize.py) и разделом `## Расшифровка`, где каждое предложение — отдельная строка вида `[ЧЧ:ММ:СС] Текст предложения.`, абзацы отделены пустой строкой, а окна, где пунктуация не восстановилась, помечены видимой пометкой перед своим блоком. Ничего, кроме этих двух разделов, в документе нет.

## Критерии приёмки

- [ ] `python tools/render_doc.py --selftest` проходит на фикстурах схемы punctuated/1 и покрывает: обычный документ, документ с окном в откате, отсутствующий файл саммари, таймкод больше часа (`01:02:03`), пустой список предложений (ошибка), перечитывание результата простым разбором строк
- [ ] Флаги: `--punctuated <путь>` (обязателен), `--summary <путь к фрагменту>` (необязателен), `--out <путь к .md>` (обязателен), `--title <строка>` (по умолчанию — имя исходной записи без расширения из поля `source`), `--selftest`, `-h/--help` со справкой на русском
- [ ] Структура документа строго такая: `# <заголовок>`, пустая строка, `## Саммари`, содержимое фрагмента саммари как есть, `## Расшифровка`, строки предложений; никаких технических блоков (модель, ×RT, SHA-256, версии, длительность) в документе нет
- [ ] Каждое предложение — одна строка `[ЧЧ:ММ:СС] текст`; часы, минуты и секунды всегда двузначные (секунды — отбрасыванием дробной части), таймкод считается от начала записи
- [ ] Абзацы из `paragraphs` разделяются одной пустой строкой; порядок предложений — по полю `index`
- [ ] Перед блоком предложений окна со `status: "fallback"` вставляется строка-пометка вида `> ⚠️ Пунктуация не восстановлена (окно N, сегменты A–B): <reason>. Ниже — дословный текст модели.`; пометка видна в отрендеренном markdown
- [ ] Если файл саммари не передан, не существует или пуст, под `## Саммари` вставляется `### Изложение` с текстом «Саммари не получено: файл <путь> отсутствует или пуст.»
- [ ] Код возврата: 0 — документ записан; 1 — документ записан, но в нём есть пометки (нет саммари или есть окна в откате); 2 — вход непригоден (нет punctuated.json, не та схема, нет предложений), файл --out не создаётся
- [ ] В stdout печатается краткий отчёт на русском: путь к итоговому файлу, его размер, число предложений и абзацев, число пометок
- [ ] Файл пишется в UTF-8, каталог для --out создаётся при необходимости; кириллица и пробелы в путях и в заголовке обрабатываются корректно
- [ ] Только стандартная библиотека, стиль и структура как у остальных tools/*.py

## Контекст

Решения владельца: итог — Markdown по пути `data/output/<имя файла>-<дата>.md`; в нём только саммари и расшифровка, технический блок не нужен; «каждое предложение — отдельная строка с префиксом [ЧЧ:ММ:СС]»; при расхождении слов место в файле помечается. Сам путь и дату выбирает вызывающий скрипт — этот инструмент только пишет туда, куда скажут через --out.

Вход 1 — файл схемы `punctuated/1` (его параллельно делает задача «tools/punctuate.py», контракт зафиксирован): `{schema: "punctuated/1", source, source_duration, transcript, model, windows: [{index, segments: [первый, последний], status: "ok"|"fallback", reason}], paragraphs: [{index, window, sentences: [первый, последний]}], sentences: [{index, start, end, text, window, fallback}], text, stats: {windows, fallback_windows, paragraphs, sentences, words}}`. Таймкоды — секунды от начала записи. Фикстуры для selftest собирай сам по этой схеме.

Вход 2 — markdown-фрагмент саммари, который пишет параллельная задача «tools/summarize.py»: три раздела уровня `###` в порядке `### Изложение`, `### Темы`, `### Решения, задачи, договорённости`, без заголовков уровня `#` и `##`. Фрагмент вставляется как есть, без переформатирования и без проверки его внутренней структуры.

Форматирование таймкодов в проекте уже есть в tools/outputs.py (`format_timestamp`) — можно повторить логику, но файл outputs.py не править: он занят рендером .txt и .srt.

Итоговые документы живут в data/, который закрыт корневым .gitignore, — текст лекции в git не попадает.

## Не входит в задачу

Не вызывать claude, не читать transcript.json и не считать таймкоды из пословных (они уже в punctuated.json), не трогать tools/outputs.py и остальные существующие инструменты, не делать .srt/.txt, не решать, как называется итоговый файл и где рабочий каталог (это задача сборочного скрипта), не добавлять технический блок в документ.

**В:** Что именно значит «точная транскрибация» в итоговом файле: дословный выход модели как есть (сплошные строчные, без точек) или текст, которому claude расставил пунктуацию и заглавные без изменения слов?  
**О:** claude расставляет пунктуацию, заглавные и абзацы, слова менять запрещено (таймкоды сохраняются)

**В:** С какой гранулярностью ставить таймкоды в итоговом файле?  
**О:** Таймкод на каждое предложение

**В:** Какой формат и куда кладётся итоговый файл?  
**О:** Markdown: data/output/<имя файла>-<дата>.md

**В:** Что должно быть в саммари и какого размера?  
**О:** Изложение + темы с таймкодами + решения/задачи/договорённости

**В:** Что делать, если claude CLI недоступен, не авторизован или упал на саммари?  
**О:** Сохранить расшифровку, вместо саммари пометка «не получено», код возврата ненулевой

**В:** Что принимает команда на входе: любой медиафайл (webm/mp4/mp3) с подготовкой 16 кГц моно WAV внутри, или по-прежнему только готовый WAV?  
**О:** Любой медиафайл, конвертация внутри, обрабатывается запись целиком

**В:** Новая команда — отдельная точка входа, а существующий scripts/transcribe_gigaam.sh остаётся как есть (бенчмарк двух моделей)?  
**О:** как будто хочется сделать общие моменты их вынести а точки входа и выхода сделать разными в разных местах соттвественно

**В:** Как вызывать claude CLI и какой моделью? Это неинтерактивный вызов из скрипта, модель влияет и на цену, и на качество пунктуации.  
**О:** claude -p <промпт> с моделью по умолчанию (её не фиксируем)

**В:** Транскрипт полной лекции (02:35) — это десятки тысяч слов, в один промпт пунктуация целиком не влезет. Резать текст на окна и склеивать результат?  
**О:** Окна по ~100 сегментов (чанков), склейка по порядку; саммари отдельным вызовом по всему тексту

**В:** Нужна ли автоматическая проверка, что claude не изменил слова (сверка последовательности слов до и после), и что делать при расхождении?  
**О:** Сверять; при расхождении в окне — взять для этого окна дословный текст без пунктуации и пометить место в файле, код возврата ненулевой

**В:** В каком виде таймкод у предложения и от какого нуля он считается?  
**О:** Каждое предложение — отдельная строка с префиксом [ЧЧ:ММ:СС]

**В:** Что ещё остаётся на диске от продуктового прогона, кроме итогового .md, и нужен ли флаг «не распознавать заново, взять готовый transcript.json и только переделать саммари/пунктуацию»?  
**О:** Промежуточные файлы (WAV, plan.json, chunks, transcript.json) в рабочем подкаталоге рядом с итогом, плюс .srt и .txt; флаг повторного прохода по готовому transcript.json есть

**В:** Нужен ли в итоговом .md технический блок (модель, режим нарезки, длительность, ×RT, SHA-256 входа, версии) и где именно?  
**О:** Нет, только саммари и расшифровка
