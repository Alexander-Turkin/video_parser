# Единый прогонный скрипт scripts/transcribe_gigaam.sh и закрытый каталог выводов

**Зависит от:** 060 070 080 090

**Правит:** scripts/transcribe_gigaam.sh data/.gitignore 

## Цель

Должен появиться один bash-скрипт scripts/transcribe_gigaam.sh, который содержит все команды прогона целиком: проверяет окружение и наличие весов, при необходимости готовит 5-минутный фрагмент, один раз строит план нарезки, затем последовательно прогоняет оба чекпойнта GigaAM на одном и том же наборе чанков под /usr/bin/time -l, рендерит .txt и .srt, запускает проверки таймкодов и печатает в stdout готовую к вставке markdown-таблицу сравнения с объективными цифрами. Плюс каталог выводов data/, закрытый собственным .gitignore, чтобы текст расшифровок реальной лекции не попал в репозиторий.

## Критерии приёмки

- [ ] `bash scripts/transcribe_gigaam.sh --help` печатает справку на русском; поддержаны флаги --input, --outdir (по умолчанию data/transcripts), --models (по умолчанию "v3_rnnt v3_e2e_rnnt"), --device (по умолчанию cpu), --download-root (по умолчанию ~/.cache/gigaam), --skip-prepare, --keep-chunks/--no-chunks или аналог для сохранения чанков, -h
- [ ] В начале прогона печатается блок окружения: дата, модель Mac и версия macOS (uname -m, sw_vers), версии ffmpeg, python, torch и gigaam, путь и размер каждого используемого чекпойнта; отдельно печатается SHA-256 входного WAV (протокол docs/research/benchmark-plan.md требует подтверждать, что вход у кандидатов одинаковый)
- [ ] Проверяется наличие ffmpeg, ffprobe, python с установленным gigaam и файлов весов <download-root>/<model>.ckpt (и <model>_tokenizer.model для e2e); при отсутствии — понятное сообщение на русском с путём и что сделать, ненулевой код возврата, прогон не начинается
- [ ] Если входного WAV нет и не передан --skip-prepare, фрагмент готовится вызовом `bash scripts/make_sample.sh` (сам make_sample.sh не менять); по умолчанию используется data/samples/Лекция_1_01.09.26_1_t4514_300s_16k_mono.wav
- [ ] План нарезки строится ровно один раз (python tools/chunker.py --input <wav> --outdir <outdir>) и используется всеми моделями, чтобы сравнение шло на побайтово одинаковых чанках; после построения печатается сводка плана (число чанков, покрытие, выброшенные паузы, мин/макс длительность чанка)
- [ ] Модели прогоняются последовательно, каждая своей командой `/usr/bin/time -l python tools/transcribe.py --plan <outdir>/plan.json --model <model> --out <outdir>/<model>/transcript.json --device <device> --download-root <root>`, вывод /usr/bin/time сохраняется в <outdir>/<model>/time.txt и пик RSS из него печатается в ГБ
- [ ] Для каждой модели после прогона вызываются python tools/outputs.py (пишет <outdir>/<model>/transcript.txt и transcript.srt) и python tools/check_timecodes.py --transcript ... --srt ... --json <outdir>/<model>/checks.json; результат проверок печатается и сохраняется в <outdir>/<model>/checks.txt
- [ ] Падение одной модели не прерывает прогон второй: ошибки собираются, в конце печатается статус по каждой модели, код возврата скрипта — ненулевой, если хоть одна модель не дала выходов или не прошла проверки, и 0, если обе прошли
- [ ] В конце печатается и сохраняется в <outdir>/summary.md готовая к вставке markdown-таблица сравнения по моделям: время загрузки модели, время распознавания, ×RT, пик RSS (ГБ), число чанков, слов и символов, число знаков .,!?, доля слов с заглавной буквы, итог проверок таймкодов (пройдено N из M); плюс строка с окружением и SHA-256 входа
- [ ] Текст расшифровок и чанки пишутся только под <outdir> внутри data/; создан файл data/.gitignore с содержимым `*` и `!.gitignore`, чтобы ничего из data/ (фрагменты, чанки, расшифровки, логи) не попало в git
- [ ] Скрипт запускается как `bash scripts/transcribe_gigaam.sh` и не требует бита исполняемости (chmod в среде раннера запрещён); начинается с set -euo pipefail, оформлен в стиле scripts/inspect_media.sh и scripts/make_sample.sh (шапка с объяснением зачем, usage, die, printf), пути с пробелами и кириллицей обрабатываются корректно
- [ ] `bash -n scripts/transcribe_gigaam.sh` проходит без ошибок
- [ ] Зарегистрирован ручной шаг для владельца с точной командой прогона: `cd "/Users/alexander/my projects/vidio_parser" && bash scripts/transcribe_gigaam.sh 2>&1 | tee "data/transcripts/run-$(date +%Y%m%d-%H%M%S).log"`, с пояснением, что прогон занимает минуты, идёт на CPU и его результат (вывод скрипта) нужен для отчёта

## Контекст

Прямое требование владельца: «сделай просто скрипт, который будет включать все нужные команды, вывод я положу в файл для дальнейшего анализа». То есть скрипт — единственная точка входа, он должен печатать в stdout всё, что понадобится для анализа, и не требовать от человека ничего, кроме одной команды. Запускать его самому не нужно и, скорее всего, нельзя: в прошлых прогонах раннеру были запрещены ffmpeg, chmod и запуск bash-скриптов (.claude-runner/SETUP.md, logs/020-denials.txt). Проверяй скрипт чтением и `bash -n`, а команду запуска оформи как ручной шаг.

Решения владельца по этому прогону: только 5-минутный фрагмент, сначала убедиться, что всё работает; сравнить v3_rnnt и v3_e2e_rnnt на одном фрагменте; веса оба уже скачаны вручную в ~/.cache/gigaam (там лежат v3_rnnt.ckpt, v3_e2e_rnnt.ckpt, v3_e2e_rnnt_tokenizer.model) — ничего не качать; фиксировать только объективное: время, ×RT, пик RSS, проверки таймкодов; текст расшифровок в репозиторий не кладём, для него отдельный каталог в gitignore.

Почему data/.gitignore, а не корневой .gitignore: корневой .gitignore и README.md принадлежат ещё не выполненной задаче tasks/040-readme-проекта-и-gitignore.md — если его править здесь, правки столкнутся. Локальный data/.gitignore с `*` и `!.gitignore` закрывает весь каталог выводов независимо от того, когда появится корневой файл. Корневой .gitignore не создавать и не трогать.

Чем пользуется скрипт (это CLI параллельных задач, контракты зафиксированы, менять их нельзя):
- `python tools/chunker.py --input <wav> --outdir <dir> [--dry-run] [--noise -35dB] [--min-silence 0.4] [--max-chunk 22] [--hard-max-chunk 24] [--min-chunk 8] [--drop-pause 2.0] [--pad 0.1]` — пишет <dir>/plan.json и <dir>/chunks/chunk_000.wav…
- `python tools/transcribe.py --plan <plan.json> --model <v3_rnnt|v3_e2e_rnnt> --out <transcript.json> --device cpu --download-root ~/.cache/gigaam`
- `python tools/outputs.py --transcript <transcript.json> --txt <файл> --srt <файл>`
- `python tools/check_timecodes.py --transcript <transcript.json> --srt <файл> --json <файл>` — код возврата 0, если все проверки прошли, 1 — если нет.
Из summary и checks.json бери цифры для таблицы; метрики времени, ×RT и пика RSS также лежат в поле metrics файла transcript.json.

Ожидаемая раскладка выводов: <outdir>/plan.json, <outdir>/chunks/, <outdir>/<model>/{transcript.json,transcript.txt,transcript.srt,time.txt,checks.json,checks.txt}, <outdir>/summary.md.

Протокол замера — docs/research/benchmark-plan.md, разделы 5 и 7 (прочитай): кандидаты запускаются последовательно, а не параллельно; ×RT = длительность аудио / время работы; пик RSS снимается через /usr/bin/time -l (на macOS печатает maximum resident set size в байтах); фиксируется окружение и SHA-256 входа. Пункт про «два прогона, холодный и тёплый» в этот раз не обязателен — владелец просил просто убедиться, что всё работает; если делаешь, то только опциональным флагом, по умолчанию выключенным.

Инструмент python берётся из .venv проекта (там стоят gigaam 0.2.0, torch, torchaudio); в PATH при запуске скрипта .venv может не быть, поэтому ищи интерпретатор так: сначала ./.venv/bin/python, иначе python3, и печатай, какой используется; если в нём нет gigaam — понятная ошибка.
