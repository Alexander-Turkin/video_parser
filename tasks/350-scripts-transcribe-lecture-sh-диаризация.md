# scripts/transcribe_lecture.sh — диаризация в конвейере, флаги --no-diarize и --diarization

**Зависит от:** 290 300 310

**Правит:** scripts/transcribe_lecture.sh 

## Цель

Продуктовая команда должна сама определять говорящих: в конвейер встают три новых шага — `tools/diarize.py`, `tools/speakers.py`, `tools/roles.py`, — а их результаты уходят в `tools/summarize.py` и `tools/render_doc.py`, чтобы в итоговом документе каждая строка расшифровки шла с ярлыком роли. Диаризация выполняется всегда, отключается флагом `--no-diarize`, а готовый файл можно подложить флагом `--diarization <путь>`. Если диаризация или привязка говорящих не удалась, прогон не останавливается: документ собирается без ярлыков, в нём стоит пометка, код возврата 1.

## Критерии приёмки

- [ ] Новые флаги в разборе аргументов и в `--help`: `--no-diarize` (шаги говорящих пропускаются целиком) и `--diarization <путь>` (взять готовый `diarization.json` вместо прогона pyannote; файл копируется в рабочий подкаталог)
- [ ] Порядок шагов: подготовка WAV → нарезка → распознавание → .txt/.srt → проверки таймкодов → **диаризация** → пунктуация → **фразы и говорящие** → **роли** → саммари → итоговый документ → чистка при `--clean`; диаризация идёт после удачного распознавания, чтобы десятки минут pyannote не тратились на прогон без транскрипта
- [ ] Каждая новая команда печатается перед запуском так же, как остальные шаги: `tools/diarize.py --input "$WAV" --out "$WORKDIR/diarization.json" --device "$DEVICE"`, `tools/speakers.py --transcript ... --punctuated ... --diarization ... --out "$WORKDIR/speakers.json"`, `tools/roles.py --speakers ... --out "$WORKDIR/roles.json" --log-dir "$CLAUDE_LOGS"`
- [ ] Удачные шаги прокидывают файлы дальше: `tools/summarize.py` получает `--speakers` и `--roles`, `tools/render_doc.py` — тоже; при неудаче любого из трёх шагов эти флаги не передаются, `render_doc.py` получает `--speakers-note "<причина>"`, выставляется FLAWED=1, и прогон завершается кодом 1 с собранным документом без ярлыков
- [ ] `--no-diarize`: три шага печатаются в статусе как пропущенные по просьбе, пометки в документе нет, FLAWED не выставляется — безупречный прогон по-прежнему даёт код 0
- [ ] `--from-transcript` без `--diarization`: шаги говорящих пропускаются так же, как уже пропускаются .txt/.srt и проверки таймкодов (без пометки в документе и без FLAWED); с `--diarization` — файл берётся, шаги фраз и ролей выполняются
- [ ] Перед прогоном печатается предупреждение, что диаризация на CPU считает примерно в реальном времени (на записи 02:35:29 это десятки минут) и что ей нужен заранее подготовленный локальный кэш pyannote; при `--no-diarize` предупреждения нет
- [ ] Наличие `tools/diarize.py`, `tools/speakers.py`, `tools/roles.py` проверяется там же, где проверяются остальные `tools/*.py`, но только когда диаризация включена; `diarization.json`, `speakers.json`, `roles.json` добавлены в блок «== Файлы прогона» и в раскладку в справке
- [ ] `bash -n scripts/transcribe_lecture.sh` чисто, `bash scripts/transcribe_lecture.sh --help` печатает обновлённую справку (новые флаги, порядок шагов, раскладка файлов, коды возврата) и код 0; последней строкой вывода прогона остаётся полный путь к итоговому `.md`, коды возврата 0/1/2 сохраняют прежний смысл

## Контекст

Ответы владельца (из `.claude-runner/plan-answers.jsonl`): «Когда делать диаризацию в продуктовом прогоне?» — «Всегда, с флагом --no-diarize на случай „не надо“»; «Что делать, если диаризация не получилась (нет весов или токена, pyannote упал, звук не читается)?» — «Собрать документ без ярлыков говорящих, пометить это в документе и вернуть код 1 (как сейчас при отсутствии claude)»; «Веса и кэш готовлю я руками, инструмент только читает локальный кэш и без него падает с кодом 2».

Устройство скрипта: общая часть (`die`, `warn`, `resolve_python`, `require_tools`, `require_weights`, `to_wav`, `print_env_block`, `plan_summary`) живёт в `scripts/lib/common.sh` и правки не требует; переменные FLAWED и NO_DOC накапливают состояние шагов, `step()` собирает статусы, блок «СТАТУС ПО ШАГАМ» печатается в конце, затем «== Файлы прогона», затем чистка при `--clean`, затем путь к документу последней строкой. Пути к файлам прогона заданы переменными рядом (`WAV`, `PLAN`, `TRANSCRIPT`, `PUNCTUATED`, `SUMMARY`, `CLAUDE_LOGS`, `LOG`) — новые файлы завести так же. Проверка claude уже есть (`tools/claude_cli.py --probe`), и теперь от claude зависят три шага, а не два — предупреждение стоит дополнить ролями.

Коды возврата инструментов, на которые надо опираться: `diarize.py` — 0 ок, 1 речи не найдено, 2 не удалось (нет кэша/пакета, звук не читается); `speakers.py` — 0 ок, 1 файл записан с оговорками, 2 вход непригоден; `roles.py` — 0 ок, 1 откат к именам «Говорящий N» (файл записан, ярлыки всё равно будут), 2 вход непригоден. Код 1 у `roles.py` — это не повод отказываться от ярлыков: файл годен, ярлыками станут имена говорящих, но прогон помечается как прошедший с пометками.

Проверить целиком на настоящей записи раннер не сможет (нужны веса GigaAM, кэш pyannote и claude), поэтому `verify` — только разбор синтаксиса и справка; что удалось прогнать руками (например, через `--from-transcript` с подложенным `diarization.json`), опиши в отчёте.
