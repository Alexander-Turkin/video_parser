# tools/render_doc.py — ярлык говорящего в каждой строке расшифровки

**Правит:** tools/render_doc.py 

## Цель

Итоговый документ должен печатать расшифровку фразами с ярлыком говорящего: `[00:12:34] Преподаватель: фраза`. Для этого `tools/render_doc.py` учится читать два новых файла — `speakers/1` (фразы с говорящими) и `roles/1` (соответствие «Говорящий N → роль») — и собирать раздел «## Расшифровка» по фразам, а не по предложениям. Без новых файлов инструмент работает ровно как сейчас. Если диаризация не получилась, документ всё равно собирается без ярлыков, но с видимой пометкой об этом и кодом возврата 1.

## Критерии приёмки

- [ ] Новые флаги: `--speakers <speakers.json>`, `--roles <roles.json>`, `--speakers-note <текст>`; описаны в `--help` по-русски
- [ ] С `--speakers` каждая строка расшифровки — одна фраза вида `[ЧЧ:ММ:СС] Ярлык: текст`; ярлык берётся из `roles/1`, если он передан, иначе это имя говорящего («Говорящий N»); у фразы без говорящего (`speaker: null`) строка остаётся прежней — `[ЧЧ:ММ:СС] текст`, без двоеточия и пустого ярлыка
- [ ] Абзацы по-прежнему разделены одной пустой строкой (границы берутся из поля `paragraph` фраз), а видимая пометка перед блоком окна со `status: "fallback"` сохраняется и указывает тот же диапазон сегментов, что и сейчас
- [ ] Без `--speakers` вывод документа не меняется ни в одном байте — расшифровка идёт предложениями, как сегодня
- [ ] `--speakers-note "<причина>"` ставит видимую строку-цитату сразу под заголовком «## Расшифровка» («ярлыки говорящих не проставлены: <причина>») и делает код возврата 1
- [ ] Негодный `speakers/1` или `roles/1` (чужая схема, битый JSON, фразы не покрывают предложения) не роняет документ: печатается предупреждение в stderr, расшифровка собирается предложениями без ярлыков, в документ встаёт та же видимая пометка, код возврата 1
- [ ] Для повторного использования из `tools/summarize.py` в модуле есть функции с фиксированными именами: `load_speakers(path)`, `load_roles(path)` и `speaker_label(phrase, roles)` — они и используются внутри рендера, а не дублируются
- [ ] Коды возврата прежние: `0` — пометок в документе нет, `1` — есть пометки, `2` — вход непригоден (и тогда `--out` не создаётся, существующий файл не перетирается); состав документа остаётся прежним — только «## Саммари» и «## Расшифровка»
- [ ] `python tools/render_doc.py --selftest` проходит, проверки на новое поведение добавлены в тот же встроенный селф-тест (строки с ярлыками, фраза без говорящего, откат при негодном `speakers/1`, `--speakers-note`, прежний вывод без `--speakers`)

## Контекст

Ответы владельца (из `.claude-runner/plan-answers.jsonl`): «Ярлык в каждой строке: `[00:12:34] Преподаватель: фраза`»; «Роли по смыслу: „Преподаватель“, „Студент 1“, „Студент 2“»; «Если диаризация не получилась — собрать документ без ярлыков говорящих, пометить это в документе и вернуть код 1 (как сейчас при отсутствии claude)»; «Нужен ли в документе состав говорящих... — Нет, достаточно ярлыков в строках расшифровки».

Схемы новых входов зафиксированы планом. `speakers/1`: `{"schema": "speakers/1", "transcript", "punctuated", "diarization", "pause", "speakers": [{"name", "label", "phrases", "speech_seconds", "share"}], "phrases": [{"index", "start", "end", "text", "speaker", "sentences": [первое, последнее], "paragraph", "fallback", "reason"}], "stats": {...}}` — фразы идут по порядку и покрывают все предложения `punctuated/1`. `roles/1`: `{"schema": "roles/1", "speakers", "status": "ok|fallback|skip", "reason", "roles": [{"speaker", "role", "share", "source"}], "stats": {...}}`.

Устройство файла сейчас: `parse_punctuated`/`load_punctuated` читают `punctuated/1`, `render_sentence` даёт строку `[ЧЧ:ММ:СС] текст` (строка 595), `render_fallback_mark` — пометку окна, `format_timecode` (строка 123) экспортируется и уже импортируется `tools/summarize.py`. Сборщик скрипта зовёт инструмент так: `python tools/render_doc.py --punctuated p.json --summary summary.md --out doc.md --title <имя>`.

Имена `load_speakers`, `load_roles`, `speaker_label` названы в плане потому, что следующая задача (`tools/summarize.py`) импортирует их отсюда и дублировать разбор `speakers/1` не должна.

## Не входит в задачу

Не менять формат `punctuated/1`, не строить фразы и не делать атрибуцию говорящих (это вход). Не добавлять в документ состав говорящих, третий раздел или заголовки помимо «## Саммари» и «## Расшифровка». Не трогать `tools/summarize.py`, `tools/speakers.py`, `tools/roles.py`, `tools/outputs.py`, `scripts/` и README.
