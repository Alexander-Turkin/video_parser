# video_parser — локальная расшифровка записей лекций

Транскрибатор записей лекций на русском. Распознавание идёт целиком на своей машине:
модель [GigaAM](https://github.com/salute-developers/GigaAM) считает на CPU, говорящих
различает локальный pyannote, платные ключи ASR-сервисов не нужны. При прогоне
пунктуация, роли и саммари используют локальную Ollama на 127.0.0.1:11434.
Текст записи во внешнюю сеть не отправляется.

**Вход** — запись лекции или созвона: любой медиафайл, который читает ffmpeg (`webm`,
`mp4`, `mp3`, `m4a`, `wav`). Конвертация в 16 кГц моно WAV идёт внутри, запись
обрабатывается целиком.

**Выход** — один markdown-файл `data/output/<имя файла>-<дата>.md`: саммари записи и
полная расшифровка, разбитая на фразы с ярлыком того, кто это сказал:
`[00:12:34] Преподаватель: фраза`. Пунктуацию, заглавные и абзацы расставляет Ollama,
**не меняя ни одного слова**: после каждого ответа последовательность слов сверяется с
дословным выходом модели. Говорящих различает по голосу pyannote — он даёт «Говорящий 1»,
«Говорящий 2», … — а Ollama поверх этого расставляет роли по смыслу разговора:
«Преподаватель» и «Студент N». Без говорящих (флаг `--no-diarize` или неудавшаяся
диаризация) строка остаётся прежней — `[ЧЧ:ММ:СС] предложение`. Все промежуточные файлы
(WAV, план нарезки, чанки, `transcript.json`, `.txt`, `.srt`, проверки, логи Ollama)
остаются в рабочем подкаталоге рядом с итогом — и убираются флагом `--clean`, если они не
нужны.

Выбранная конфигурация — **GigaAM `v3_rnnt` с нарезкой без выбрасывания пауз**: она дала
лучший WER на замере, см. раздел 8
[`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md).

## Требования

* **macOS на Apple Silicon.** Проверено на Apple M5 / macOS 26.6.2.
* **ffmpeg и ffprobe:** `brew install ffmpeg`.
* **Python 3.12 в `.venv` проекта** с установленными `gigaam` 0.2.0 и `torch`. Скрипты
  сами берут `./.venv/bin/python`, если он есть, иначе `python3` из `PATH`. Пакет GigaAM
  ставится из его репозитория:

  ```bash
  git clone https://github.com/salute-developers/GigaAM.git
  cd GigaAM && pip install -e ".[torch]"
  ```

  Extra `[longform]` не нужен: `transcribe_longform()` тянет pyannote и требует
  `HF_TOKEN`, а здесь длинная запись режется своим нарезчиком. Говорящих определяет
  отдельный шаг на своём pyannote — см. пункт про диаризацию ниже.
* **Веса GigaAM в `~/.cache/gigaam`, скачанные заранее.** Нужны:

  | Модель | Файлы |
  | --- | --- |
  | `v3_rnnt` | `v3_rnnt.ckpt` |
  | `v3_e2e_rnnt` | `v3_e2e_rnnt.ckpt`, `v3_e2e_rnnt_tokenizer.model` |

  **Инструменты репозитория ничего не качают.** Перед загрузкой модели
  `tools/transcribe.py` проверяет файлы и без них падает с кодом `2` и сообщением, в
  котором назван полный путь к недостающему файлу; `scripts/transcribe_gigaam.sh`
  проверяет то же до начала прогона. Другой каталог с весами задаётся флагом
  `--download-root`.
* **Ollama и модель `qwen3:8b` для пунктуации, ролей и саммари.** Установите
  [Ollama](https://ollama.com/download), выполните `ollama pull qwen3:8b` и
  запустите локальный сервер. Проверка: `python tools/ollama_client.py --probe`.
  Скрипт подключается к `127.0.0.1:11434`; имя модели можно сменить для всех
  трёх шагов через `--ollama-model <имя>`. При недоступной модели исходный
  транскрипт и итоговый документ сохраняются с видимыми пометками, код возврата `1`.
* **Диаризация: пакет `pyannote.audio` в `.venv` проекта и локальный кэш Hugging Face,
  подготовленный заранее.** Шаг `tools/diarize.py` определяет по звуку, кто и когда
  говорил, моделью `pyannote/speaker-diarization-community-1`. Пакет в `.venv` уже стоит,
  а вот **веса и кэш готовит человек руками**: инструменты репозитория не качают ничего —
  ни конфигурации пайплайна, ни весов, — и перед импортом pyannote выставляется
  `HF_HUB_OFFLINE=1`, так что в сеть шаг не пойдёт даже случайно.

  Кэш готовится один раз, тремя шагами. Репозиторий модели **gated**, поэтому сначала
  условия доступа принимаются аккаунтом на
  <https://hf.co/pyannote/speaker-diarization-community-1> — без этого отдадут 403; если
  пайплайн тянет модели из соседних репозиториев, условия надо принять и у них, их имена
  назовёт сама закачка. Затем создаётся токен чтения (<https://hf.co/settings/tokens>).
  И только на третьем шаге, самой закачке, этот токен нужен:

  ```bash
  HF_HOME=~/.cache/huggingface HF_TOKEN=hf_... \
      python -c "from huggingface_hub import snapshot_download; \
  snapshot_download('pyannote/speaker-diarization-community-1')"
  ```

  **Самому инструменту `HF_TOKEN` не нужен никогда.** Перед загрузкой модели он проверяет,
  что в кэше лежит годный снапшот — файл
  `<кэш>/hub/models--pyannote--speaker-diarization-community-1/snapshots/<снапшот>/config.yaml`
  (проверяется именно он, а не наличие каталога: оборвавшаяся закачка оставляет снапшот со
  ссылками на несуществующие блобы). Снапшота нет — шаг падает с кодом `2` и сообщением, в
  котором названы репозиторий, каталог кэша, полный путь к ожидаемому файлу, причина и те
  же три шага подготовки. Каталог кэша по умолчанию — `$HF_HOME`, иначе
  `~/.cache/huggingface`; другой задаётся флагом `--cache-dir`, другая модель — `--model`.

Во время прогона данные остаются на машине: распознавание, диаризация и текстовые
шаги работают локально. `HF_TOKEN` нужен только для разовой ручной закачки весов pyannote.

## Быстрый старт

Из корня репозитория — одна команда на всю работу:

```bash
bash scripts/transcribe_lecture.sh --input "vidio_example/Лекция 1.webm"
```

Скрипт сам приводит вход к 16 кГц моно WAV, режет его по тишине **без выбрасывания пауз**,
распознаёт `v3_rnnt`, рендерит `.txt` и `.srt`, проверяет таймкоды, определяет pyannote,
кто и когда говорил, расставляет Ollama пунктуацию окнами, собирает фразы с говорящими,
определяет их роли, делает саммари через Ollama и выпускает итоговый документ. Каждая команда печатается перед запуском,
весь вывод дублируется в `run.log`, а последняя строка — полный путь к итоговому `.md`.

Итог лежит в `data/output/<имя файла>-<дата>.md`: `<имя файла>` — имя входного файла без
расширения, `<дата>` — `ГГГГ-ММ-ДД`. Для команды выше это
`data/output/Лекция 1-2026-10-03.md`. Существующий файл не перетирается: если итог с таким
именем уже есть, к имени добавляется `-ЧЧММСС`.

Коды возврата: `0` — итог собран, пунктуация восстановлена во всех окнах, саммари получено,
проверки таймкодов пройдены и ярлыки говорящих проставлены (сюда же относится прогон с
`--no-diarize`: выключенные по просьбе шаги говорящих пометкой не считаются); `1` — итог
собран, но в нём есть пометки (нет саммари, есть окна с дословным текстом, провалены
проверки, **не вышли говорящие**); `2` — расшифровку получить не удалось, итогового `.md`
нет.

**Говорящие определяются всегда** — флага «включить диаризацию» нет, есть флаг выключить.
Шаг стоит после распознавания и он самый долгий. По умолчанию pyannote считает на
видеоядре Mac (`--diarize-device auto` выбирает `mps`, если оно есть, иначе `cpu`): запись
02:35:29 на Apple M5 заняла 14:42. На CPU тот же pyannote идёт примерно в реальном времени
(10-минутный фрагмент — 10:25), то есть такая лекция — это часы. Разметка на `mps` и на
`cpu` совпала до миллисекунды (DER 0% на 10-минутном фрагменте, замер 2026-10-04).
Распознавание GigaAM от этого флага не зависит — им управляет `--device`. Скрипт
предупреждает о времени перед прогоном — там же напоминание про локальный кэш (см.
«Требования»). Пока шаг идёт, каждая строка прогресса показывает, сколько прошло и
сколько осталось, а в конце шага — сколько он занял: по двум соседним строкам видно, что
прогон не завис. Варианты сэкономить ещё два:

* `--no-diarize` — говорящие не нужны: шаги диаризации, фраз и ролей пропускаются целиком,
  расшифровка идёт предложениями без ярлыков. Это **не пометка**: безупречный прогон с этим
  флагом по-прежнему даёт код `0`;
* `--diarization <путь>` — взять готовый `diarization.json` схемы `diarization/1` вместо
  прогона pyannote: файл копируется в рабочий подкаталог, фразы и роли считаются как
  обычно. С `--no-diarize` несовместим.

Если говорящие были нужны и не вышли — нет кэша pyannote (код `2` у шага), не ответил
Ollama на ролях, не сошлись фразы, — прогон не прерывается: документ собирается **без
ярлыков говорящих**, под заголовком «## Расшифровка» встаёт видимая пометка с причиной, а
код возврата становится `1`.

Полезные флаги: `--outdir` (куда класть итог и рабочий подкаталог, по умолчанию
`data/output`), `--model`, `--device` (устройство GigaAM), `--diarize-device` (устройство
pyannote, по умолчанию `auto`), `--download-root`, `--window <N>` (сколько сегментов
уходит Ollama в одном окне пунктуации, по умолчанию 25), `--no-chunks` (удалить чанки
после распознавания) и `--from-transcript <путь>` — взять готовый `transcript.json` и
переделать только пунктуацию, саммари и документ: конвертация, нарезка, распознавание и
проверки пропускаются, веса GigaAM не нужны. Шаги говорящих при `--from-transcript`
пропускаются тоже — звука под рукой уже нет, — и это не пометка; нужны ярлыки — добавьте
`--diarization <путь>` с готовым файлом.

Флаг `--clean` убирает за прогоном: после сборки документа скрипт зовёт
`tools/cleanup_runs.py --run <рабочий подкаталог>`, и от подкаталога остаются только
результаты шагов — `transcript.json`, `diarization.json`, `punctuated.json`, `summary.md`,
`roles.json` и `speakers.json`. **Чистит только при коде возврата `0`:**
при `1` (в итоге есть пометки) и при `2` (итога нет) не удаляется ничего — промежуточные
файлы нужны, чтобы разобраться, — а причина пропуска печатается. Удаляется в том числе
`run.log`: на экран прогон допишется до конца, но лога на диске после `--clean` не будет, и
восстановить удалённое нечем.

Режим нарезки у этой команды не настраивается: нарезчику всегда уходит `--drop-pause 86400`,
то есть паузы не выбрасываются — иначе в расшифровке лекции появились бы дыры на месте
выброшенной тишины.

Полный список — `bash scripts/transcribe_lecture.sh --help`.

## Бенчмарк чекпойнтов

Отдельная команда, **не** способ расшифровать запись: она не даёт ни саммари, ни
пунктуации, ни итогового markdown. Её задача — прогнать по одному плану нарезки оба
чекпойнта GigaAM (`v3_rnnt` и `v3_e2e_rnnt`) и сравнить их между собой. Для обычной
расшифровки нужна команда из «Быстрого старта».

```bash
mkdir -p data/transcripts && bash scripts/transcribe_gigaam.sh 2>&1 | tee "data/transcripts/run-$(date +%Y%m%d-%H%M%S).log"
```

`mkdir -p` здесь обязателен: без каталога падает `tee`, а не скрипт. Скрипт готовит
фрагмент (если входного WAV нет), строит один план нарезки на все модели, прогоняет по
нему каждый чекпойнт под `/usr/bin/time -l`, рендерит `.txt` и `.srt`, проверяет таймкоды и
пишет сравнительную таблицу. Выход — в `data/transcripts/` (раскладка ниже, в
«Результатах»). Код возврата `0` — все модели дали выходы и прошли проверки.

Прогон идёт на **CPU** (`--device cpu` по умолчанию). На 5-минутном фрагменте каждая
модель отрабатывает примерно за 8 секунд: 1,0–1,1 с загрузка модели плюс ~6,3 с
распознавание, около 39×RT, пик RSS 1,8 ГБ — замеры из
[`docs/analysis/gigaam-local-run.md`](docs/analysis/gigaam-local-run.md). Там же **расчёт**
(не замер) для полной записи 02:35:29 — порядка 3,3 минуты на распознавание.

На полной записи созвона (27:51, 1670,998 с) каждая модель отрабатывает примерно за минуту:
2,0–2,1 с загрузка плюс 62–63 с распознавание, 25,5–26,9×RT, пик RSS 1,5–1,8 ГБ — замеры из
раздела 6 [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md).

Полезные флаги: `--input` (свой WAV), `--models "v3_rnnt"` (прогнать одну модель),
`--outdir`, `--download-root`, `--no-chunks` (удалить чанки после прогона),
`--skip-prepare`, а также два флага нарезки:

* `--drop-pause <сек>` — порог длинной паузы, пробрасывается в `tools/chunker.py`: паузы
  длиннее порога выбрасываются из чанков;
* `--keep-pauses` — не выбрасывать паузы вовсе (нарезчику уходит `--drop-pause 86400`):
  покрытие равно длительности входа, в `.srt` нет дыр. При обоих флагах сильнее
  `--keep-pauses`, с предупреждением в stderr. Выбранный режим печатается в сводке плана и
  в `summary.md`. Это **рекомендуемый режим**: см. решение в разделе 8
  [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md). Продуктовая команда
  работает только в нём и флагов нарезки не имеет.

Полный список — `bash scripts/transcribe_gigaam.sh --help`.

## Что внутри

Каждый из инструментов `tools/` — самостоятельный CLI со встроенным `--selftest`, который
проходит без ffmpeg, без весов моделей, без кэша pyannote и без установленного Ollama.
Тяжёлые зависимости нужны только на прогоне: `transcribe.py` импортирует torch и gigaam
лениво, `diarize.py` — pyannote, остальные обходятся стандартной библиотекой. Справка у
всех — `--help`.

### Скрипты

* **`scripts/transcribe_lecture.sh`** — продуктовая команда: медиафайл на вход, один
  markdown на выход. Шаги по порядку: `to_wav` → `tools/chunker.py` →
  `tools/transcribe.py` → `tools/outputs.py` → `tools/check_timecodes.py` →
  `tools/diarize.py` → `tools/punctuate.py` → `tools/speakers.py` → `tools/roles.py` →
  `tools/summarize.py` → `tools/render_doc.py`, при `--clean` в конце ещё
  `tools/cleanup_runs.py`. Диаризация стоит после распознавания: это самый долгий шаг
  (на видеоядре Mac лекция 02:35:29 — около 15 минут, на CPU — примерно в реальном
  времени), и на прогон, который до транскрипта может и не дойти, это время тратить
  незачем. Команда — см. «Быстрый старт».
* **`scripts/transcribe_gigaam.sh`** — бенчмарк двух чекпойнтов: окружение, веса, нарезка,
  распознавание каждым чекпойнтом под `/usr/bin/time -l`, рендер, проверки и
  `summary.md` со сравнительной таблицей. Команда — см. «Бенчмарк чекпойнтов».
* **`scripts/lib/common.sh`** — общая часть обоих прогонов: поиск python из `.venv`,
  проверка ffmpeg, весов и пакета gigaam, блоки «окружение» и «вход» в логе, сводка плана
  нарезки и `to_wav` — приведение любого медиафайла к 16 кГц моно `pcm_s16le` (перекодирование
  пропускается, если вход уже такой WAV). Подключается через `source`, при подключении
  ничего не делает; проверить `to_wav` на настоящем файле —
  `bash scripts/lib/common.sh --selftest <медиафайл> <каталог>`.
* **`scripts/make_sample.sh`** — вырезает из длинной записи фрагмент из середины: 16 кГц
  моно WAV для ASR и короткое видео для сверки глазами, печатает длительности и SHA-256.
  `bash scripts/make_sample.sh --duration 300`.
* **`scripts/inspect_media.sh`** — технический разбор медиафайла: контейнер и кодеки,
  длительность, битрейты, громкость (EBU R128) и доля тишины.
  `bash scripts/inspect_media.sh "vidio_example/запись.webm"`.

### Инструменты

* **`tools/chunker.py`** — ищет тишину через `ffmpeg silencedetect`, режет по центрам
  пауз под лимит модели и пишет `plan.json` схемы `chunk-plan/1` плюс чанки в `chunks/`.
  Флаги: `--input`, `--outdir`, `--plan`, `--dry-run`, `--noise`, `--min-silence`,
  `--max-chunk`, `--hard-max-chunk`, `--min-chunk`, `--drop-pause`, `--pad`, `--selftest`.
  `python tools/chunker.py --input data/samples/a.wav --dry-run`.
* **`tools/transcribe.py`** — прогоняет GigaAM по готовому плану и пишет один JSON схемы
  `transcript/1` с сегментами, словами и метриками. Флаги: `--plan`,
  `--model {v3_rnnt,v3_e2e_rnnt}`, `--out`, `--device`, `--download-root`, `--selftest`.
  `python tools/transcribe.py --plan data/transcripts/plan.json --out out.json`.
* **`tools/outputs.py`** — рендерит из транскрипта `.txt` и `.srt`; кадры субтитров
  собираются по пословным таймкодам, а не по сегментам. Флаги: `--transcript`, `--txt`,
  `--srt`, `--max-line`, `--max-lines`, `--max-cue`, `--gap`, `--selftest`.
  `python tools/outputs.py --transcript out.json --txt out.txt --srt out.srt`.
* **`tools/check_timecodes.py`** — объективные проверки годности результата: монотонность
  и корректность сегментов, вложенность пословных таймкодов, границы записи, полнота,
  покрытие, отсутствие зацикливания, валидность SRT. Печатает таблицу PASS/FAIL и итог.
  Флаги: `--transcript`, `--srt`, `--json`, `--tolerance`, `--selftest`. Коды возврата:
  `0` — всё прошло, `1` — есть FAIL, `2` — вход непригоден.
  `python tools/check_timecodes.py --transcript out.json --srt out.srt`.
* **`tools/diarize.py`** — определяет по подготовленному 16 кГц моно WAV, кто и когда
  говорил, и пишет один JSON схемы `diarization/1`: говорящие («Говорящий N» по порядку
  первого появления голоса, исходная метка pyannote — в `speakers[].label`), реплики
  `turns` с границами и именем, `stats`. Перекрывающиеся интервалы сохраняются как есть и
  **не склеиваются** — так видно перебивки, а суммарная длительность одновременной речи
  лежит в `stats.overlap_seconds`. Ролей здесь нет: инструмент слышит голоса, но не знает,
  кто преподаватель. **Веса не скачиваются никогда:** перед загрузкой модели проверяется
  локальный кэш Hugging Face (см. «Требования»), а сам импорт pyannote идёт с
  `HF_HUB_OFFLINE=1`. Инструмент не вызывает ffmpeg и ничего не конвертирует.
  `--device auto` (по умолчанию) считает на видеоядре Mac, если оно есть, иначе на CPU;
  в файл пишется устройство, на котором считали, а длительность каждого шага pyannote —
  в `stats.step_seconds`. Флаги:
  `--input`, `--out`, `--model`, `--cache-dir`, `--device`, `--min-speakers`,
  `--max-speakers`, `--selftest`. Коды возврата: `0` — файл записан, найден хотя бы один
  говорящий; `1` — файл записан, но речи не нашлось (`turns` пуст); `2` — вход непригоден,
  нет пакета `pyannote.audio`, нет кэша модели, pyannote упал или звук не читается, и тогда
  `--out` не создаётся, а существующий не перетирается.
  `python tools/diarize.py --input audio.wav --out diarization.json`.
* **`tools/ollama_client.py`** — общий локальный HTTP-клиент для пунктуации,
  ролей и саммари. Проверяет наличие модели, сохраняет промпты и ответы по вызовам.
  `python tools/ollama_client.py --probe`.
* **`tools/punctuate.py`** — расставляет пунктуацию, заглавные и абзацы силами Ollama,
  **не меняя слов**: режет сегменты на окна по `--window`, после каждого ответа сверяет
  последовательность слов с транскриптом и пишет JSON схемы `punctuated/1` — предложения с
  таймкодами, абзацы и окна. Флаги: `--transcript`, `--out`, `--window`, `--timeout`,
  `--attempts`, `--ollama-model`, `--log-dir`, `--selftest`. Коды возврата: `0` — все окна прошли сверку,
  `1` — есть окна в откате (файл всё равно записан), `2` — вход непригоден.
  `python tools/punctuate.py --transcript t.json --out p.json`.
* **`tools/speakers.py`** — соединяет три источника: пословные таймкоды `transcript/1`,
  предложения с пунктуацией и абзацами `punctuated/1` и интервалы говорящих
  `diarization/1`, — и пишет JSON схемы `speakers/1`: расшифровку, разбитую на фразы, у
  каждой время начала и конца, текст с пунктуацией и имя говорящего. Границы фразы ставятся
  ровно по трём правилам — граница абзаца, смена говорящего и пауза между соседними словами
  не меньше `--pause` (по умолчанию 1,0 с); верхнего предела длины фразы нет, однословная
  фраза остаётся отдельной фразой. Ролей инструмент не знает. Флаги: `--transcript`,
  `--punctuated`, `--diarization`, `--out`, `--pause`, `--selftest`. Коды возврата: `0` —
  все фразы получили говорящего и все предложения выровнялись, `1` — есть фразы без
  говорящего или невыровненные предложения (файл всё равно записан), `2` — вход непригоден,
  `--out` не создаётся.
  `python tools/speakers.py --transcript t.json --punctuated p.json --diarization d.json --out s.json`.
* **`tools/roles.py`** — одним вызовом Ollama решает, кто из говорящих кто по смыслу
  разговора, и пишет JSON схемы `roles/1` — соответствие «Говорящий N → роль».
  «Преподаватель» один, остальные — «Студент 1», «Студент 2», … с нумерацией по убыванию
  доли речи. В промпт по каждому говорящему уходят имя, доля речи, число фраз и до 15
  показательных фраз с таймкодами; ответ разбирается терпимо — лишние строки игнорируются,
  роль приводится к одной строке не длиннее 40 символов, неназванный говорящий получает
  «Студент N», а если «Преподавателем» названы несколько, роль остаётся у того, кто больше
  говорил. Говорящий всего один — «Преподаватель» без вызова Ollama; говорящих нет вовсе —
  пустое соответствие со статусом «skip». Флаги: `--speakers`, `--out`, `--timeout`,
  `--attempts`, `--ollama-model`, `--log-dir`, `--selftest`. Коды возврата: `0` — роли получены (в том числе
  когда говорящий один или их нет), `1` — Ollama не ответил или ответ негоден: файл
  записан, но роли в нём равны именам говорящих и стоит статус «fallback» с причиной,
  `2` — вход непригоден.
  `python tools/roles.py --speakers s.json --out roles.json`.
* **`tools/summarize.py`** — саммари записи через Ollama по умолчанию: короткую запись
  обрабатывает одним запросом, длинную делит по таймкодам на части и объединяет.
  Семь списочных разделов объединяются без нового обращения к модели; связное
  изложение сводится отдельным запросом. Результат —
  markdown-фрагмент с восемью разделами уровня `###`, всегда в этом порядке — «Изложение»
  (связный текст, 3–8 абзацев, без списков и таймкодов), «Ключевые моменты», «Темы»,
  «Домашние задания», «Сроки и дедлайны», «Решения, задачи, договорённости», «Термины и
  определения», «Материалы и ссылки». В семи списочных разделах каждая строка —
  `- [ЧЧ:ММ:СС] текст`, таймкод обязателен (строка без него во фрагмент не попадает), а
  раздел, в котором перечислять нечего, получает одну строку «не прозвучало». Домашнее
  задание записывается как `- [ЧЧ:ММ:СС] задание — срок: …`, и тот же срок повторяется
  отдельной строкой в «Сроках и дедлайнах»; если срок в записи не прозвучал, в той же
  позиции стоит `срок: не назван`. **Срок цитируется так, как сказано** («к следующему
  занятию», «через две недели»), а дата в скобках добавляется только когда она прямо
  названа в записи («до 15 октября»): пересчёт относительных сроков в даты промпт
  запрещает — сегодняшнего числа инструмент не знает. С `--speakers` расшифровка подаётся
  модели не предложениями, а фразами говорящих — строками `[ЧЧ:ММ:СС] Ярлык: текст`, — и
  промпт требует ярлык ровно **в двух разделах из восьми**: «Домашние задания» и «Решения,
  задачи, договорённости» (`- [ЧЧ:ММ:СС] Преподаватель: задание — срок: …`). Остальные
  шесть не меняются, и в «Сроках и дедлайнах» по-прежнему повторяется срок из строки
  задания. Ярлык — роль из `--roles`, без него имя говорящего; негодный `speakers/1` или
  `roles/1` саммари не отменяет: причина уходит в stderr, а фрагмент делается по
  предложениям без ярлыков. Флаги: `--punctuated`, `--transcript`
  (подстраховка, если пунктуации ещё нет), `--speakers`, `--roles`, `--out`, `--timeout`,
  `--attempts`, `--log-dir`, `--ollama-model`, `--selftest`.
  Коды возврата: `0` — саммари получено, `1` — не получено (файл записан с пометкой и
  причиной), `2` — вход непригоден.
  `python tools/summarize.py --punctuated p.json --out summary.md`.
* **`tools/render_doc.py`** — собирает итоговый документ: заголовок, «## Саммари» (фрагмент
  вставляется как есть) и «## Расшифровка» строками `[ЧЧ:ММ:СС] предложение`, абзацы
  разделены пустой строкой. Ничего, кроме этих двух разделов, в документе нет. С
  `--speakers` расшифровка собирается не по предложениям, а по фразам говорящих, и каждая
  строка получает ярлык — `[00:12:34] Преподаватель: текст фразы.`; ярлык берётся из
  `--roles`, а без него им служит имя говорящего («Говорящий 1»). У фразы, которой
  диаризация говорящего не дала, строка остаётся прежней, без ярлыка. Флаг
  `--speakers-note <текст>` ставит под заголовком «## Расшифровка» видимую пометку с
  причиной, по которой ярлыков не будет, и даёт код `1`. Негодный `speakers/1` или
  `roles/1` документ не роняет: причина в stderr, расшифровка предложениями, пометка в
  документе, код `1`. Флаги: `--punctuated`, `--out`, `--summary`, `--speakers`, `--roles`,
  `--speakers-note`, `--title`, `--selftest`. Коды возврата: `0` — пометок в документе нет,
  `1` — есть пометки (нет саммари, окна в откате или не проставлены ярлыки говорящих),
  `2` — вход непригоден.
  `python tools/render_doc.py --punctuated p.json --speakers s.json --roles roles.json --summary summary.md --out doc.md`.
* **`tools/cleanup_runs.py`** — чистит рабочие подкаталоги прогонов в `data/output`: в
  каталоге остаются только шесть файлов-хранителей — `transcript.json`,
  `diarization.json`, `punctuated.json`, `summary.md`, `roles.json` и `speakers.json`, — а
  всё прочее удаляется (`audio.wav`, `plan.json`, `chunks/`, `.txt`,
  `.srt`, `checks.*`, `ollama/`, `run.log`, любые другие файлы и подкаталоги, вложенные —
  рекурсивно); каталог, в котором не осталось ни одного хранителя, удаляется целиком. Без
  аргументов берутся все непосредственные подкаталоги `data/output` (итоговые `.md` прямо в
  нём не трогаются никогда), `--run <каталог>` — ровно один указанный. По символическим
  ссылкам инструмент не переходит: `audio.wav`-ссылка только отвязывается, исходная запись
  за пределами каталога цела. **Удаление необратимо** — ни корзины, ни архива, поэтому
  сначала `--dry-run`. Флаги: `--run`, `--dry-run`, `--selftest`, `--help`. Коды возврата:
  `0` — отработано (в том числе когда чистить нечего и когда каталога нет), `1` — что-то
  удалить не удалось, `2` — ошибка в аргументах или `--run` указывает на несуществующий путь
  либо не на каталог.
  `python tools/cleanup_runs.py --dry-run`.

## Результаты

Продуктовый прогон кладёт в `data/output/` итоговый документ и рабочий подкаталог рядом с
ним — одно имя на двоих:

```
data/output/
├── Лекция 1-2026-10-03.md      итог: «## Саммари» и «## Расшифровка»
└── Лекция 1-2026-10-03/        рабочий подкаталог того же прогона
    ├── audio.wav               16 кГц моно WAV (ссылка на вход, если он уже такой)
    ├── plan.json               план нарезки, схема chunk-plan/1
    ├── chunks/chunk_000.wav …  чанки (нет при --no-chunks)
    ├── transcript.json         дословный выход модели, схема transcript/1
    ├── transcript.txt          читаемый текст без таймкодов
    ├── transcript.srt          субтитры по пословным таймкодам
    ├── checks.json             проверки таймкодов, схема checks/1
    ├── checks.txt              таблица PASS/FAIL
    ├── diarization.json        кто и когда говорил, схема diarization/1
    ├── punctuated.json         предложения с пунктуацией, схема punctuated/1
    ├── speakers.json           фразы с говорящими, схема speakers/1
    ├── roles.json              роли говорящих, схема roles/1
    ├── summary.md              фрагмент саммари
    ├── ollama/                 промпты и ответы всех текстовых шагов
    └── run.log                 весь вывод прогона
```

Трёх файлов говорящих — `diarization.json`, `speakers.json`, `roles.json` — не будет, если
шаги говорящих не выполнялись: при `--no-diarize`, при `--from-transcript` без
`--diarization` или когда соответствующий шаг упал. При `--diarization <путь>` готовый
`diarization.json` лежит там же, просто он скопирован, а не посчитан.

В итоговом `.md` только два раздела: в «Саммари» вставлен фрагмент из восьми разделов
уровня «###» (см. `tools/summarize.py` выше), а в «Расшифровке» каждая фраза — своя строка
`[ЧЧ:ММ:СС] Преподаватель: фраза`, таймкод считается от начала записи; абзацы отделены
пустой строкой. **Состава говорящих в документе нет** — ни списка ролей, ни долей речи, ни
числа реплик: только ярлык в начале каждой строки. Кому какой голос достался, видно в
`speakers.json` и `roles.json` рабочего подкаталога. Если говорящих не определяли или
определить не вышло, строка выглядит по-старому — `[ЧЧ:ММ:СС] предложение`, — а в
неудачном случае под заголовком «## Расшифровка» стоит видимая пометка с причиной. Если
пунктуация в каком-то окне не восстановилась, перед его блоком стоит видимая строка-цитата
с причиной и номерами сегментов, а ниже идёт дословный текст модели.

После чистки — флагом `--clean` у прогона или отдельным вызовом
`python tools/cleanup_runs.py` по всем прогонам сразу — раскладка становится такой:
итоговый `.md` и рядом подкаталог ровно из шести файлов (тех, что дались дороже всего).

```
data/output/
├── Лекция 1-2026-10-03.md      итог: «## Саммари» и «## Расшифровка»
└── Лекция 1-2026-10-03/        рабочий подкаталог после чистки
    ├── transcript.json         дословный выход модели, схема transcript/1
    ├── diarization.json        кто и когда говорил, схема diarization/1
    ├── punctuated.json         предложения с пунктуацией, схема punctuated/1
    ├── speakers.json           фразы с говорящими, схема speakers/1
    ├── roles.json              роли говорящих, схема roles/1
    └── summary.md              фрагмент саммари
```

Всё остальное — `audio.wav`, `plan.json`, `chunks/`, `.txt`, `.srt`, `checks.*`, `ollama/` и
`run.log` — удалено **безвозвратно**: в корзину файлы не уходят и восстановить их нечем, а
подкаталог, в котором не осталось ни одного из этих шести файлов, удаляется целиком.
После прогона с `--no-diarize` файлов остаётся три: чистка оставляет те из шести, что есть.
Посмотреть список до удаления — `python tools/cleanup_runs.py --dry-run`.

Бенчмарк пишет своё, в `data/transcripts/`:

```
data/transcripts/
├── plan.json                   план нарезки, схема chunk-plan/1
├── chunks/chunk_000.wav …      чанки, 16 кГц моно pcm_s16le
├── summary.md                  сравнительная таблица по моделям
├── run-<дата>-<время>.log      полный вывод прогона (если запускали через tee)
├── v3_rnnt/
│   ├── transcript.json         схема transcript/1
│   ├── transcript.txt          читаемый текст
│   ├── transcript.srt          субтитры
│   ├── time.txt                stderr прогона и блок /usr/bin/time -l
│   ├── checks.json             схема checks/1
│   └── checks.txt              таблица PASS/FAIL
└── v3_e2e_rnnt/                те же шесть файлов
```

Фрагменты, подготовленные `make_sample.sh`, — в `data/samples/`.

**В git ничего из этого не попадает.** Корневой `.gitignore` закрывает `/data/` целиком и
`/vidio_example` с исходными записями, а также `.venv/` и медиафайлы по расширениям.
Расшифровки реальной лекции остаются только на диске; чтобы получить их у себя, надо
прогнать скрипт.

## Ограничения

* **Чанк не длиннее 24 с.** `transcribe()` в gigaam 0.2.0 бросает `ValueError` на входе
  длиннее 25 с, поэтому нарезчик держит абсолютный предел 24 с (рабочий — 22 с).
* **У самого нарезчика паузы длиннее 2 с по умолчанию выбрасываются** (`--drop-pause`):
  так прогон чуть быстрее, но в `.srt` на месте пауз остаются дыры. Проверка покрытия об
  этом знает и сверяется с `plan.json`, так что объяснённые планом разрывы нарушением не
  считаются. На замере экономия оказалась меньше секунды на 28 минутах, поэтому выбранный
  режим — без выбрасывания пауз: продуктовая команда работает только в нём, в бенчмарке он
  включается флагом `--keep-pauses`.
* **Пунктуация восстанавливается отдельным шагом, и он обращается к локальному серверу Ollama.** `v3_rnnt` выдаёт
  сплошной поток строчными, без точек и заглавных (`v3_e2e_rnnt` пунктуацию ставит сам, но
  проигрывает по WER и требует ещё файл токенизатора). Поэтому после распознавания
  `tools/punctuate.py` режет сегменты на окна по 25 штук, отправляет каждое окно Ollama
  по порядку и без перекрытия — в контекст кладётся последнее предложение предыдущего окна —
  и склеивает ответы. Промпт прямо запрещает менять, добавлять, удалять и переставлять
  слова; **на слово промпту никто не верит**: последовательность слов в ответе
  нормализуется и поэлементно сверяется с транскриптом. Если слова разошлись или Ollama не
  ответил, окно откатывается к дословному тексту модели без пунктуации, в документе перед
  его блоком встаёт видимая пометка с причиной и номерами сегментов, а код возврата
  становится ненулевым. Остальные окна при этом обрабатываются как обычно.
* **Говорящие определяются, но качество этого не замерено.** Диаризацию pyannote никто не
  сверял с размеченной записью: ни ошибки назначения, ни числа найденных голосов не
  посчитано, цифр привести нечем. Там, где говорят одновременно, ярлык у фразы может
  оказаться чужим: pyannote сохраняет перекрывающиеся интервалы как есть, слово достаётся
  тому, с чьим интервалом оно пересекается сильнее, а говорящим фразы становится тот, чьих
  слов в ней больше по суммарной длительности. Роли — «Преподаватель», «Студент N» — ставит
  Ollama по смыслу разговора, то есть он и может ошибиться: перепутать роли, если
  преподаватель говорит мало, или назвать студентом второго ведущего. Проверить это можно
  только глазами, по `speakers.json` и `roles.json`. А если шаг говорящих не вышел совсем —
  нет кэша pyannote, не ответил Ollama, не сошлись фразы, — ярлыков в документе **не будет
  вовсе**: расшифровка соберётся предложениями, с пометкой о причине и кодом возврата `1`.
* **Точность замерена, но верхней оценкой.** 2026-10-03 оба чекпойнта прогнаны на всей
  записи рабочего созвона (27:51) в двух режимах нарезки и сравнены с готовой
  расшифровкой: лучший результат — `v3_rnnt` с `--keep-pauses`, **WER 12,32 %**, WER без

  таймкодов. Эталон не вычитывался дословно (он причёсан и числа в нём цифрами), поэтому

  эталону не посчитать. Числа и разбор — в разделах 3 и 6
  [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md), подробный отчёт
