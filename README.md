# vidio_parser — локальная расшифровка записей лекций

Транскрибатор записей лекций на русском. Распознавание идёт целиком на своей машине:
модель [GigaAM](https://github.com/salute-developers/GigaAM) считает на CPU, платные
ключи ASR-сервисов не нужны. В сеть ходит только шаг расстановки пунктуации и саммари —
через локально установленный Claude CLI.

**Вход** — запись лекции или созвона: любой медиафайл, который читает ffmpeg (`webm`,
`mp4`, `mp3`, `m4a`, `wav`). Конвертация в 16 кГц моно WAV идёт внутри, запись
обрабатывается целиком.

**Выход** — один markdown-файл `data/output/<имя файла>-<дата>.md`: саммари записи и
полная расшифровка, где каждое предложение — отдельная строка `[ЧЧ:ММ:СС] предложение`.
Пунктуацию, заглавные и абзацы расставляет claude, **не меняя ни одного слова**: после
каждого ответа последовательность слов сверяется с дословным выходом модели. Все
промежуточные файлы (WAV, план нарезки, чанки, `transcript.json`, `.txt`, `.srt`,
проверки, логи claude) остаются в рабочем подкаталоге рядом с итогом — и убираются флагом
`--clean`, если они не нужны.

Выбранная конфигурация — **GigaAM `v3_rnnt` с нарезкой без выбрасывания пауз**: она дала
лучший WER на замере, см. раздел 8
[`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md).

---

## Требования

* **macOS на Apple Silicon.** Проверено на Apple M5 / macOS 26.6.2.
* **ffmpeg и ffprobe:** `brew install ffmpeg`.
* **Python 3.12 в `.venv` проекта** с установленными `gigaam` 0.2.0 и `torch`. Скрипты
  сами берут `./.venv/bin/python`, если он есть, иначе `python3` из `PATH`. Пакет GigaAM
  ставится из его репозитория:

  ```bash
  git clone https://github.com/salute-developers/GigaAM.git
  cd GigaAM && pip install -e ".[torch]"
  ```

  Extra `[longform]` не нужен: `transcribe_longform()` тянет pyannote и требует
  `HF_TOKEN`, а здесь длинная запись режется своим нарезчиком.
* **Веса GigaAM в `~/.cache/gigaam`, скачанные заранее.** Нужны:

  | Модель | Файлы |
  | --- | --- |
  | `v3_rnnt` | `v3_rnnt.ckpt` |
  | `v3_e2e_rnnt` | `v3_e2e_rnnt.ckpt`, `v3_e2e_rnnt_tokenizer.model` |

  **Инструменты репозитория ничего не качают.** Перед загрузкой модели
  `tools/transcribe.py` проверяет файлы и без них падает с кодом `2` и сообщением, в
  котором назван полный путь к недостающему файлу; `scripts/transcribe_gigaam.sh`
  проверяет то же до начала прогона. Другой каталог с весами задаётся флагом
  `--download-root`.
* **Claude CLI — бинарник `claude` в `PATH`, установленный и авторизованный заранее.**
  Нужен двум шагам продуктового прогона: восстановлению пунктуации и саммари. Вызов
  всегда один и тот же — `claude -p <промпт>`, **модель не задаётся** (используется модель
  по умолчанию), интерактивные и потоковые флаги не передаются, stdin закрыт. Весь вызов
  собран в одном месте, `tools/claude_cli.py`; путь к бинарнику можно задать переменной
  окружения `CLAUDE_BIN`. Проверка, что вызывать есть чем: `python tools/claude_cli.py
  --probe` (живого запроса не делает, поэтому про авторизацию не говорит — её видно только
  по ответу самого claude).

  **Без claude прогон не падает:** расшифровка всё равно сохраняется и итоговый `.md`
  собирается — просто текст в нём дословный, без пунктуации, каждое окно помечено строкой
  «Пунктуация не восстановлена», а вместо саммари стоит пометка «не получено» с причиной.
  Код возврата при этом ненулевой (`1`).

Распознавание, нарезка, рендер и проверки работают локально и в сеть не ходят: платные
ключи и токены нужны только тому Claude CLI, который вы ставите отдельно.

## Быстрый старт

Из корня репозитория — одна команда на всю работу:

```bash
bash scripts/transcribe_lecture.sh --input "vidio_example/Лекция 1.webm"
```

Скрипт сам приводит вход к 16 кГц моно WAV, режет его по тишине **без выбрасывания пауз**,
распознаёт `v3_rnnt`, рендерит `.txt` и `.srt`, проверяет таймкоды, расставляет claude
пунктуацию окнами и собирает итоговый документ. Каждая команда печатается перед запуском,
весь вывод дублируется в `run.log`, а последняя строка — полный путь к итоговому `.md`.

Итог лежит в `data/output/<имя файла>-<дата>.md`: `<имя файла>` — имя входного файла без
расширения, `<дата>` — `ГГГГ-ММ-ДД`. Для команды выше это
`data/output/Лекция 1-2026-10-03.md`. Существующий файл не перетирается: если итог с таким
именем уже есть, к имени добавляется `-ЧЧММСС`.

Коды возврата: `0` — итог собран, пунктуация восстановлена во всех окнах, саммари получено
и проверки таймкодов пройдены; `1` — итог собран, но в нём есть пометки (нет саммари, есть
окна с дословным текстом, провалены проверки); `2` — расшифровку получить не удалось,
итогового `.md` нет.

Полезные флаги: `--outdir` (куда класть итог и рабочий подкаталог, по умолчанию
`data/output`), `--model`, `--device`, `--download-root`, `--window <N>` (сколько сегментов
уходит claude в одном окне пунктуации, по умолчанию 100), `--no-chunks` (удалить чанки
после распознавания) и `--from-transcript <путь>` — взять готовый `transcript.json` и
переделать только пунктуацию, саммари и документ: конвертация, нарезка, распознавание и
проверки пропускаются, веса GigaAM не нужны.

Флаг `--clean` убирает за прогоном: после сборки документа скрипт зовёт
`tools/cleanup_runs.py --run <рабочий подкаталог>`, и от подкаталога остаются только
`transcript.json`, `punctuated.json` и `summary.md`. **Чистит только при коде возврата `0`:**
при `1` (в итоге есть пометки) и при `2` (итога нет) не удаляется ничего — промежуточные
файлы нужны, чтобы разобраться, — а причина пропуска печатается. Удаляется в том числе
`run.log`: на экран прогон допишется до конца, но лога на диске после `--clean` не будет, и
восстановить удалённое нечем.

Режим нарезки у этой команды не настраивается: нарезчику всегда уходит `--drop-pause 86400`,
то есть паузы не выбрасываются — иначе в расшифровке лекции появились бы дыры на месте
выброшенной тишины.

Полный список — `bash scripts/transcribe_lecture.sh --help`.

## Бенчмарк чекпойнтов

Отдельная команда, **не** способ расшифровать запись: она не даёт ни саммари, ни
пунктуации, ни итогового markdown. Её задача — прогнать по одному плану нарезки оба
чекпойнта GigaAM (`v3_rnnt` и `v3_e2e_rnnt`) и сравнить их между собой. Для обычной
расшифровки нужна команда из «Быстрого старта».

```bash
mkdir -p data/transcripts && bash scripts/transcribe_gigaam.sh 2>&1 | tee "data/transcripts/run-$(date +%Y%m%d-%H%M%S).log"
```

`mkdir -p` здесь обязателен: без каталога падает `tee`, а не скрипт. Скрипт готовит
фрагмент (если входного WAV нет), строит один план нарезки на все модели, прогоняет по
нему каждый чекпойнт под `/usr/bin/time -l`, рендерит `.txt` и `.srt`, проверяет таймкоды и
пишет сравнительную таблицу. Выход — в `data/transcripts/` (раскладка ниже, в
«Результатах»). Код возврата `0` — все модели дали выходы и прошли проверки.

Прогон идёт на **CPU** (`--device cpu` по умолчанию). На 5-минутном фрагменте каждая
модель отрабатывает примерно за 8 секунд: 1,0–1,1 с загрузка модели плюс ~6,3 с
распознавание, около 39×RT, пик RSS 1,8 ГБ — замеры из
[`docs/analysis/gigaam-local-run.md`](docs/analysis/gigaam-local-run.md). Там же **расчёт**
(не замер) для полной записи 02:35:29 — порядка 3,3 минуты на распознавание.

На полной записи созвона (27:51, 1670,998 с) каждая модель отрабатывает примерно за минуту:
2,0–2,1 с загрузка плюс 62–63 с распознавание, 25,5–26,9×RT, пик RSS 1,5–1,8 ГБ — замеры из
раздела 6 [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md).

Полезные флаги: `--input` (свой WAV), `--models "v3_rnnt"` (прогнать одну модель),
`--outdir`, `--download-root`, `--no-chunks` (удалить чанки после прогона),
`--skip-prepare`, а также два флага нарезки:

* `--drop-pause <сек>` — порог длинной паузы, пробрасывается в `tools/chunker.py`: паузы
  длиннее порога выбрасываются из чанков;
* `--keep-pauses` — не выбрасывать паузы вовсе (нарезчику уходит `--drop-pause 86400`):
  покрытие равно длительности входа, в `.srt` нет дыр. При обоих флагах сильнее
  `--keep-pauses`, с предупреждением в stderr. Выбранный режим печатается в сводке плана и
  в `summary.md`. Это **рекомендуемый режим**: см. решение в разделе 8
  [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md). Продуктовая команда
  работает только в нём и флагов нарезки не имеет.

Полный список — `bash scripts/transcribe_gigaam.sh --help`.

## Что внутри

Каждый из инструментов `tools/` — самостоятельный CLI со встроенным `--selftest`, который
проходит без ffmpeg, без весов моделей и без установленного claude. Тяжёлые зависимости
нужны только на прогоне: `transcribe.py` импортирует torch и gigaam лениво, остальные
обходятся стандартной библиотекой. Справка у всех — `--help`.

### Скрипты

* **`scripts/transcribe_lecture.sh`** — продуктовая команда: медиафайл на вход, один
  markdown на выход. Шаги по порядку: `to_wav` → `tools/chunker.py` →
  `tools/transcribe.py` → `tools/outputs.py` → `tools/check_timecodes.py` →
  `tools/punctuate.py` → `tools/summarize.py` → `tools/render_doc.py`, при `--clean` в конце
  ещё `tools/cleanup_runs.py`. Команда — см. «Быстрый старт».
* **`scripts/transcribe_gigaam.sh`** — бенчмарк двух чекпойнтов: окружение, веса, нарезка,
  распознавание каждым чекпойнтом под `/usr/bin/time -l`, рендер, проверки и
  `summary.md` со сравнительной таблицей. Команда — см. «Бенчмарк чекпойнтов».
* **`scripts/lib/common.sh`** — общая часть обоих прогонов: поиск python из `.venv`,
  проверка ffmpeg, весов и пакета gigaam, блоки «окружение» и «вход» в логе, сводка плана
  нарезки и `to_wav` — приведение любого медиафайла к 16 кГц моно `pcm_s16le` (перекодирование
  пропускается, если вход уже такой WAV). Подключается через `source`, при подключении
  ничего не делает; проверить `to_wav` на настоящем файле —
  `bash scripts/lib/common.sh --selftest <медиафайл> <каталог>`.
* **`scripts/make_sample.sh`** — вырезает из длинной записи фрагмент из середины: 16 кГц
  моно WAV для ASR и короткое видео для сверки глазами, печатает длительности и SHA-256.
  `bash scripts/make_sample.sh --duration 300`.
* **`scripts/inspect_media.sh`** — технический разбор медиафайла: контейнер и кодеки,
  длительность, битрейты, громкость (EBU R128) и доля тишины.
  `bash scripts/inspect_media.sh "vidio_example/запись.webm"`.

### Инструменты

* **`tools/chunker.py`** — ищет тишину через `ffmpeg silencedetect`, режет по центрам
  пауз под лимит модели и пишет `plan.json` схемы `chunk-plan/1` плюс чанки в `chunks/`.
  Флаги: `--input`, `--outdir`, `--plan`, `--dry-run`, `--noise`, `--min-silence`,
  `--max-chunk`, `--hard-max-chunk`, `--min-chunk`, `--drop-pause`, `--pad`, `--selftest`.
  `python tools/chunker.py --input data/samples/a.wav --dry-run`.
* **`tools/transcribe.py`** — прогоняет GigaAM по готовому плану и пишет один JSON схемы
  `transcript/1` с сегментами, словами и метриками. Флаги: `--plan`,
  `--model {v3_rnnt,v3_e2e_rnnt}`, `--out`, `--device`, `--download-root`, `--selftest`.
  `python tools/transcribe.py --plan data/transcripts/plan.json --out out.json`.
* **`tools/outputs.py`** — рендерит из транскрипта `.txt` и `.srt`; кадры субтитров
  собираются по пословным таймкодам, а не по сегментам. Флаги: `--transcript`, `--txt`,
  `--srt`, `--max-line`, `--max-lines`, `--max-cue`, `--gap`, `--selftest`.
  `python tools/outputs.py --transcript out.json --txt out.txt --srt out.srt`.
* **`tools/check_timecodes.py`** — объективные проверки годности результата: монотонность
  и корректность сегментов, вложенность пословных таймкодов, границы записи, полнота,
  покрытие, отсутствие зацикливания, валидность SRT. Печатает таблицу PASS/FAIL и итог.
  Флаги: `--transcript`, `--srt`, `--json`, `--tolerance`, `--selftest`. Коды возврата:
  `0` — всё прошло, `1` — есть FAIL, `2` — вход непригоден.
  `python tools/check_timecodes.py --transcript out.json --srt out.srt`.
* **`tools/claude_cli.py`** — единственное место, где проект запускает Claude CLI:
  `claude -p <промпт>` с моделью по умолчанию, без интерактивных флагов и с закрытым
  stdin. Умеет повторять попытку (на таймауте и ненулевом коде), различает «claude
  недоступен» и «вызов не удался» и складывает промпты с ответами по файлу на вызов. Одновременно библиотека для
  `punctuate.py` и `summarize.py`. Флаги: `--probe`, `--ask <файл|->`, `--timeout`,
  `--attempts`, `--log-dir`, `--tag`, `--selftest`.
  `python tools/claude_cli.py --probe`.
* **`tools/punctuate.py`** — расставляет пунктуацию, заглавные и абзацы силами claude,
  **не меняя слов**: режет сегменты на окна по `--window`, после каждого ответа сверяет
  последовательность слов с транскриптом и пишет JSON схемы `punctuated/1` — предложения с
  таймкодами, абзацы и окна. Флаги: `--transcript`, `--out`, `--window`, `--timeout`,
  `--attempts`, `--log-dir`, `--selftest`. Коды возврата: `0` — все окна прошли сверку,
  `1` — есть окна в откате (файл всё равно записан), `2` — вход непригоден.
  `python tools/punctuate.py --transcript t.json --out p.json`.
* **`tools/summarize.py`** — саммари записи одним вызовом claude по всему тексту:
  markdown-фрагмент с восемью разделами уровня `###`, всегда в этом порядке — «Изложение»
  (связный текст, 3–8 абзацев, без списков и таймкодов), «Ключевые моменты», «Темы»,
  «Домашние задания», «Сроки и дедлайны», «Решения, задачи, договорённости», «Термины и
  определения», «Материалы и ссылки». В семи списочных разделах каждая строка —
  `- [ЧЧ:ММ:СС] текст`, таймкод обязателен (строка без него во фрагмент не попадает), а
  раздел, в котором перечислять нечего, получает одну строку «не прозвучало». Домашнее
  задание записывается как `- [ЧЧ:ММ:СС] задание — срок: …`, и тот же срок повторяется
  отдельной строкой в «Сроках и дедлайнах»; если срок в записи не прозвучал, в той же
  позиции стоит `срок: не назван`. **Срок цитируется так, как сказано** («к следующему
  занятию», «через две недели»), а дата в скобках добавляется только когда она прямо
  названа в записи («до 15 октября»): пересчёт относительных сроков в даты промпт
  запрещает — сегодняшнего числа инструмент не знает. Флаги: `--punctuated`, `--transcript`
  (подстраховка, если пунктуации ещё нет), `--out`, `--timeout`, `--attempts`, `--log-dir`,
  `--selftest`.
  Коды возврата: `0` — саммари получено, `1` — не получено (файл записан с пометкой и
  причиной), `2` — вход непригоден.
  `python tools/summarize.py --punctuated p.json --out summary.md`.
* **`tools/render_doc.py`** — собирает итоговый документ: заголовок, «## Саммари» (фрагмент
  вставляется как есть) и «## Расшифровка» строками `[ЧЧ:ММ:СС] предложение`, абзацы
  разделены пустой строкой. Ничего, кроме этих двух разделов, в документе нет. Флаги:
  `--punctuated`, `--out`, `--summary`, `--title`, `--selftest`. Коды возврата: `0` —
  пометок в документе нет, `1` — есть пометки, `2` — вход непригоден.
  `python tools/render_doc.py --punctuated p.json --summary summary.md --out doc.md`.
* **`tools/cleanup_runs.py`** — чистит рабочие подкаталоги прогонов в `data/output`: в
  каталоге остаются только три файла-хранителя — `transcript.json`, `punctuated.json` и
  `summary.md`, — а всё прочее удаляется (`audio.wav`, `plan.json`, `chunks/`, `.txt`,
  `.srt`, `checks.*`, `claude/`, `run.log`, любые другие файлы и подкаталоги, вложенные —
  рекурсивно); каталог, в котором не осталось ни одного хранителя, удаляется целиком. Без
  аргументов берутся все непосредственные подкаталоги `data/output` (итоговые `.md` прямо в
  нём не трогаются никогда), `--run <каталог>` — ровно один указанный. По символическим
  ссылкам инструмент не переходит: `audio.wav`-ссылка только отвязывается, исходная запись
  за пределами каталога цела. **Удаление необратимо** — ни корзины, ни архива, поэтому
  сначала `--dry-run`. Флаги: `--run`, `--dry-run`, `--selftest`, `--help`. Коды возврата:
  `0` — отработано (в том числе когда чистить нечего и когда каталога нет), `1` — что-то
  удалить не удалось, `2` — ошибка в аргументах или `--run` указывает на несуществующий путь
  либо не на каталог.
  `python tools/cleanup_runs.py --dry-run`.

## Результаты

Продуктовый прогон кладёт в `data/output/` итоговый документ и рабочий подкаталог рядом с
ним — одно имя на двоих:

```
data/output/
├── Лекция 1-2026-10-03.md      итог: «## Саммари» и «## Расшифровка»
└── Лекция 1-2026-10-03/        рабочий подкаталог того же прогона
    ├── audio.wav               16 кГц моно WAV (ссылка на вход, если он уже такой)
    ├── plan.json               план нарезки, схема chunk-plan/1
    ├── chunks/chunk_000.wav …  чанки (нет при --no-chunks)
    ├── transcript.json         дословный выход модели, схема transcript/1
    ├── transcript.txt          читаемый текст без таймкодов
    ├── transcript.srt          субтитры по пословным таймкодам
    ├── checks.json             проверки таймкодов, схема checks/1
    ├── checks.txt              таблица PASS/FAIL
    ├── punctuated.json         предложения с пунктуацией, схема punctuated/1
    ├── summary.md              фрагмент саммари
    ├── claude/                 промпты и ответы claude по вызовам
    └── run.log                 весь вывод прогона
```

В итоговом `.md` только два раздела: в «Саммари» вставлен фрагмент из восьми разделов
уровня «###» (см. `tools/summarize.py` выше), а в «Расшифровке» каждое предложение — своя
строка `[ЧЧ:ММ:СС] предложение`, таймкод считается от начала записи; абзацы отделены пустой
строкой. Если пунктуация в каком-то окне не восстановилась, перед его блоком стоит видимая
строка-цитата с причиной и номерами сегментов, а ниже идёт дословный текст модели.

После чистки — флагом `--clean` у прогона или отдельным вызовом
`python tools/cleanup_runs.py` по всем прогонам сразу — раскладка становится такой:
итоговый `.md` и рядом подкаталог ровно из трёх файлов.

```
data/output/
├── Лекция 1-2026-10-03.md      итог: «## Саммари» и «## Расшифровка»
└── Лекция 1-2026-10-03/        рабочий подкаталог после чистки
    ├── transcript.json         дословный выход модели, схема transcript/1
    ├── punctuated.json         предложения с пунктуацией, схема punctuated/1
    └── summary.md              фрагмент саммари
```

Всё остальное — `audio.wav`, `plan.json`, `chunks/`, `.txt`, `.srt`, `checks.*`, `claude/` и
`run.log` — удалено **безвозвратно**: в корзину файлы не уходят и восстановить их нечем, а
подкаталог, в котором не осталось ни одного из трёх файлов, удаляется целиком. Посмотреть
список до удаления — `python tools/cleanup_runs.py --dry-run`.

Бенчмарк пишет своё, в `data/transcripts/`:

```
data/transcripts/
├── plan.json                   план нарезки, схема chunk-plan/1
├── chunks/chunk_000.wav …      чанки, 16 кГц моно pcm_s16le
├── summary.md                  сравнительная таблица по моделям
├── run-<дата>-<время>.log      полный вывод прогона (если запускали через tee)
├── v3_rnnt/
│   ├── transcript.json         схема transcript/1
│   ├── transcript.txt          читаемый текст
│   ├── transcript.srt          субтитры
│   ├── time.txt                stderr прогона и блок /usr/bin/time -l
│   ├── checks.json             схема checks/1
│   └── checks.txt              таблица PASS/FAIL
└── v3_e2e_rnnt/                те же шесть файлов
```

Фрагменты, подготовленные `make_sample.sh`, — в `data/samples/`.

**В git ничего из этого не попадает.** Корневой `.gitignore` закрывает `/data/` целиком и
`/vidio_example` с исходными записями, а также `.venv/` и медиафайлы по расширениям.
Расшифровки реальной лекции остаются только на диске; чтобы получить их у себя, надо
прогнать скрипт.

## Ограничения

* **Чанк не длиннее 24 с.** `transcribe()` в gigaam 0.2.0 бросает `ValueError` на входе
  длиннее 25 с, поэтому нарезчик держит абсолютный предел 24 с (рабочий — 22 с).
* **У самого нарезчика паузы длиннее 2 с по умолчанию выбрасываются** (`--drop-pause`):
  так прогон чуть быстрее, но в `.srt` на месте пауз остаются дыры. Проверка покрытия об
  этом знает и сверяется с `plan.json`, так что объяснённые планом разрывы нарушением не
  считаются. На замере экономия оказалась меньше секунды на 28 минутах, поэтому выбранный
  режим — без выбрасывания пауз: продуктовая команда работает только в нём, в бенчмарке он
  включается флагом `--keep-pauses`.
* **Пунктуация восстанавливается отдельным шагом, и он ходит в сеть.** `v3_rnnt` выдаёт
  сплошной поток строчными, без точек и заглавных (`v3_e2e_rnnt` пунктуацию ставит сам, но
  проигрывает по WER и требует ещё файл токенизатора). Поэтому после распознавания
  `tools/punctuate.py` режет сегменты на окна по 100 штук, отправляет каждое окно claude
  по порядку и без перекрытия — в контекст кладётся последнее предложение предыдущего окна —
  и склеивает ответы. Промпт прямо запрещает менять, добавлять, удалять и переставлять
  слова; **на слово промпту никто не верит**: последовательность слов в ответе
  нормализуется и поэлементно сверяется с транскриптом. Если слова разошлись или claude не
  ответил, окно откатывается к дословному тексту модели без пунктуации, в документе перед
  его блоком встаёт видимая пометка с причиной и номерами сегментов, а код возврата
  становится ненулевым. Остальные окна при этом обрабатываются как обычно.
* **Точность замерена, но верхней оценкой.** 2026-10-03 оба чекпойнта прогнаны на всей
  записи рабочего созвона (27:51) в двух режимах нарезки и сравнены с готовой
  расшифровкой: лучший результат — `v3_rnnt` с `--keep-pauses`, **WER 12,32 %**, WER без
  чисел 12,26 %, CER 7,89 %, медиана сдвига таймкодов 0,253 с, все 9 из 9 проверок
  таймкодов. Эталон не вычитывался дословно (он причёсан и числа в нём цифрами), поэтому
  это **верхняя оценка**: реальная ошибка модели, скорее всего, ниже, а насколько — по этому
  эталону не посчитать. Числа и разбор — в разделах 3 и 6
  [`docs/research/benchmark-plan.md`](docs/research/benchmark-plan.md), подробный отчёт
  лежит локально в `docs/analysis/reference-metrics.md` (в git не версионируется, как и
  сами расшифровки).
* **На полной лекции 02:35:29 прогона не было.** Замер сделан на 28-минутной записи; как
  пайплайн ведёт себя на записи в шесть раз длиннее — не проверено.
* **Кандидаты вне GigaAM не сравнивались.** whisper.cpp и faster-whisper не замерялись:
  их веса надо качать из сети. Выбор сделан только между двумя чекпойнтами GigaAM.
* **Форма поставки не выбрана.** Веб-сервис это будет или Telegram-бот — решение не
  принято, поэтому ядро сделано CLI-пайплайном, не зависящим от интерфейса.
